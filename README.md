# AD&C Shared Knowledge（旧AgentOS-C Shared Knowledge）

人生の重要な場面で、主要な議論・主張・根拠・反論を比較できるようにし、調べる時間を短縮する公開共有知の基盤です。最上位の目的は、本人のより良い選択を支えることです。

> **AD&Cの宣言｜完成形のない仕組みで、完成する仕事を増やす。**
>
> 人もAIも不完全で、使う環境も変わり続けます。AD&Cは、完璧な論理体系や万能のAIを完成させるのではなく、**自然言語で既存のAI・知識・道具をつなぎ、安全・機能・分かりやすさ・人間の時間の釣り合いを、その都度実物で確かめて改善し続けるシカケ**です。
>
> **仕組みに最終完成はなくても、個々の仕事には完了条件があります。** 「できた」は成果物・保存・読戻しで確かめ、「できなかった」は原因と次の手段を残します。誤りや不完全さを放置する免罪符にはしません。
>
> この小さな改善を重ね、**人の選択と暮らしを助け、社会に価値を広げることを目指します。** 成功率・時間削減・生活の質（QOL）への効果は、実測していない限り実証済みとは言いません。背景と開発判断の基準は[開発リーダー正本のグランドデザイン原則](docs/templates/LEADER_WORKSHEET.md#adc-grand-design-engineering-principle-approved-2026-11-04)を参照してください。


**読んで使うだけでも参加できます。共有知の更新への協力は任意です。** 個人の相談、利用履歴、健康・家族・購入情報を提供する必要はありません。

### 理念と実行Playbookの境界（2026-11-09）

**Playbook共通標準（2026-11-11・本人正式採用）**：新設・今後の実質改訂は、**日本語正本を保持／機械的ナビを段階的にPythonへ／ボタン実装は各AIのUI／変更前後のSHA-256・日本語差分を検知し局所整合**。新規Playbookは[テンプレートの上部参照・パス規約](templates/PLAYBOOK_TEMPLATE.md)を使用。実行・変更検知の具体手順は[開発プラクティス](docs/DEVELOPMENT_WORKFLOW_PRACTICES.md)を正本とし、ここに二重記載しない。**動画・サムネイルの創作工程は現行の採用済み方式を維持し、将来の移行は本人の別途判断**。既存ファイルの一括移行や通常利用者へのSHA検査はしない。

**近傍配置・最小中央管理**：LinuxのREADME／設定ファイルと同様、各Playbookの使い方・設計理由・関連ツールは原則その対象のそばに置き、中央は発見用リンクと共通契約だけにする。全PlaybookのPython一括適用や設計理由の毎回読込はしない。

**自然な会話の1行コア（入口を読んだAI向け）**：AD&C関連の通常応答は**まず依頼を実行**し、返答の最後に「次の有効な人間操作」があれば[標準コミュニケーション](skills/communication-navigation/SKILL.md)の**実動する主ボタン0〜2件＋補助『もう一声』原則1件**へつなぐ。主ボタンのために架空の次仕事や再承認を作らない。専門Playbookのボタン0件・結果入力待ち・専用UIを優先し、対応しないAIでは短い日本語の操作案内にする。毎回答の全標準再取得・長いチェック表は不要。 **複数工程の計画では「出力／次の一手」を最後の1工程として先に予約し、結果をまとめた直後にこの共通出口を適用する。** これは毎回の全文再取得やリーダーワークシート読込みを意味せず、専門の固定出力・0ボタン・入力待ちを優先する。

**改善・トラブル解消なら**「ループで」と言われなくても[ループ方式選択](skills/loop-development/SKILL.md)の**小さな内×閉（観測→局所修正→検証→必要な再修正）**を原則とする。成功時は終了し、固定3巡・無限反復・外部定時タスク新設はしない。普通の質問・単発制作・相談だけには強制しない。

## AD&Cの理念との関係

**どんな玄人も、専門外では素人だ。** AD&C（AI-DODAI & Continuity）は、分野の玄人が当然知っている基本知識・手順・判断基準を共有できる形で整え、AIが利用者の状況に応じて案内することを目指します。**玄人の「当たり前」はAIが案内。人間は、その先の判断に集中する。**

人間の判断を置き換えたり、誰もが専門家になれると約束したりするものではありません。出典・反論・適用条件・更新状況を示し、重要な選択と承認は本人に残します。正式配布カタログのActive項目は現在0件ですが、山歩き・チャット引継ぎ・環境構築・標準コミュニケーションの試用項目は4件あります。理念全体の実装・効果が検証済みという意味ではありません。

## 何をしようとしているか

一から大量の情報を調べなくても、主要な主張、支持・反対の理由、未解決点、関連する専門家の実際の見解へ到達できる比較資料を育てます。答え・勝者・推奨行動の提示は必須にしません。個人差と科学的知識の更新を前提に、異論や判断が分かれる条件を残します。

- 確立した知見だけでなく、有力な仮説も根拠・不確実性・リスクを区別して扱う。
- 人気や投稿数を正しさとせず、出典の質・独立性・反証・適用条件を確認する。
- 主張ごとに専門家の公開発言・論文を紐付ける。発信者、監修者、相談先を区別し、必要時だけ本人に合う候補を検討する。
- 誤りは訂正し、重大な問題は撤回する。古い版を利用している人にも追跡可能な記録を残す。
- 最終的な選択は本人が行い、結果を保証しない。妥当な判断過程と偶然の成功を区別する。
