# AD&C Shared Knowledge（旧AgentOS-C Shared Knowledge）

人生の重要な場面で、主要な議論・主張・根拠・反論を比較できるようにし、調べる時間を短縮する公開共有知の基盤です。最上位の目的は、本人のより良い選択を支えることです。

> **AD&Cの宣言｜完成形のない仕組みで、完成する仕事を増やす。**
>
> 人もAIも不完全で、使う環境も変わり続けます。AD&Cは、完璧な論理体系や万能のAIを完成させるのではなく、**自然言語で既存のAI・知識・道具をつなぎ、安全・機能・分かりやすさ・人間の時間の釣り合いを、その都度実物で確かめて改善し続けるシカケ**です。
>
> **仕組みに最終完成はなくても、個々の仕事には完了条件があります。** 「できた」は成果物・保存・読戻しで確かめ、「できなかった」は原因と次の手段を残します。誤りや不完全さを放置する免罪符にはしません。
>
> この小さな改善を重ね、**人の選択と暮らしを助け、社会に価値を広げることを目指します。** 成功率・時間削減・生活の質（QOL）への効果は、実測していない限り実証済みとは言いません。背景と開発判断の基準は[開発リーダー正本のグランドデザイン原則](docs/templates/LEADER_WORKSHEET.md#adc-grand-design-engineering-principle-approved-2026-11-04)を参照してください。


**読んで使うだけでも参加できます。共有知の更新への協力は任意です。** 個人の相談、利用履歴、健康・家族・購入情報を提供する必要はありません。

### 全担当共通：正本データの書込みと参照同期（2026-11-02／採用）

**既存のKB・Skill・Playbookを更新するAI（秘書、リーダー、担当者を含む）は、書込み前に対象KBの現行START_HERE→registry/INDEX→そのKBの統合更新手順を実取得し、その手順と権限・停止条件を優先する。** この公開READMEは、個人KBの非公開Playbookを代替する実行正本ではない。

変更は「原本の変更」だけでなく「同一ID・変更前ハッシュ・保全/復旧・競合確認 → 実書込み → 原本の再取得 → 実SHA/版の計算 → registry/INDEX/Contextなど依存先の局所同期 → 再取得・逆引き検証」を一組として扱う。**一つでも必須工程が不一致/未実行ならDONEにしない。** 登録されている旧ハッシュを現行の証拠と推定せず、原因未確定のエラーは原因ゲートNG。安全な独立工程は続ける。

この一般規則の共有は**自動インストール/各AIが受領・実行した証明ではない**。非公開のKB原文・Drive ID/URL・個人情報・認証情報を公開リポジトリへ転記しない。公開mainの更新・リリースは既存の審査/承認境界を維持する。**開発リーダー宛ての報告・続報・判断依頼を受けたAIは、報告文や委任文を作る前に[開発リーダー実行正本](docs/templates/LEADER_WORKSHEET.md)の現行main全文を取得し、既存親ID・最新証跡・本人承認・実装/読戻しゲートに従って自分が受領・判断・安全な実装を行う。** 自分が現任リーダーなら架空の別担当へ再委任せず、受領/記録/実装/独立検収を分離して報告する。正本が取得できない場合は再試行1回後にNOT_RUNと原因・再開条件を残す。通常チャットへのこのREADME/Playbookの自動注入や他AIの実行は保証されず、Q1〜Q4の独立試験は別判定。リーダーの実行時確認は[既存ワークシート](docs/templates/LEADER_WORKSHEET.md)を参照。

### 全担当共通：チャット引継ぎ・コンテクスト圧縮（2026-11-03／利用者採用・試用）

**開発リーダー・秘書・日次／半月次の定例担当・調査・PR・制作など、担当AIやチャットが交代するときは、[U字型チャット引継ぎPlaybook](skills/chat-handoff/SKILL.md)を共通の引継ぎ方式として参照する。** 初期の役割と長期方針・最近の実務を優先し、中間は重要決定・承認・失敗原因・未完了の元工程だけを残す。定例秘書業務では回答済みの質問や旧い完了報告を復活させず、現行レビュー・タスク設定・未決の一問に接続する。 **実行先を変更できないスケジュールタスクは、本人の移管指示があれば旧タスク停止と同条件の後継1件作成で置換し、両設定を読戻す。開発体制のない個人秘書やリマインダーにも適用する。**動画／サムネイル等の創作成果物の固定仕様・正規素材は非圧縮とし、制作工程への機械的な一括適用はしない。

**本方式は利用者採用の共通試用標準。** 各担当の現行正本と書込手順を置換しない。新AIの実取得・受領・再開、機能の自動配布、効果は別々に検証し、未実施は `NOT_RUN`。配布カタログの正式 `items` には昇格させない。

### 全担当共通：コピペ指示文の書式と独立試験の命名（2026-11-03／利用者指示）

**別チャット・別AI・ツールに貼り付ける実行指示は、全文を1つのMarkdownコードブロック（フェンス）内に表示する。** 指示本文の前後にある解説・検証状況はブロックの外へ分離し、リンク・案件ID・検収条件・報告先など貼付に必要な要素をブロック内から落とさない。人間への通常の説明文、専門の制作物の固定書式、JSON/API等の厳格な入出力形式を不用意に書き換えない。

**独立試験の指示文は、1行目を必ず「対象名＋独立試験」とする。** 例：`AD&C 開発リーダーPlaybook 独立試験`、`AD&C 山歩きPlaybook 独立試験`。`独立試験｜対象名`や単独の`独立試験`を先頭に置かず、チャット一覧で対象が判別できるようにする。開発・秘書・調査・制作・一般のチャット引継ぎで共通適用し、個別Playbookへ同文を大量複製しない。**指示の提示／相手の取得／独立試験実行は別判定**。別AIへの自動適用は保証しない。


### 全担当共通：共通規則の版確認ゲート（2026-11-03／限定試行）

実行型Playbookの作業開始時に、共通規則の現行版を機械的に確認する。**共通規則の更新を検出したら、変更後の全文を実取得・再確認してから作業を続ける。** 新チャット・前回の取得証跡がない場合も全文取得する。未変更なら、当該チャット／実行環境で前回の全文取得・確認が証明できる場合だけ再利用する。別チャットのローカル状態を共通の既読証拠にしない。

読取専用の限定試行ツール：[共通規則SHAゲート](skills/common-rule-version-gate/check.py)。対象は公開GitHub mainの共有READMEとAD&C本体の共通実行標準。`python check.py --state .adnc-common-rule-state.json` で現在のGit blob SHAを照会し、`SAME` (exit 0) / `CHANGED` (exit 10) / `UNKNOWN` (exit 20) / `INVALID_STATE` (exit 30) を返す。初回はCHANGEDとなる。**CHANGED時は更新後の正本全文を別途取得・確認**し、取得したSHAと一致するものだけ `--acknowledge-sha shared=SHA --acknowledge-sha execution=SHA` で記録する。ツール自体は全文読解もPlaybook実行も行わない。UNKNOWNや取得失敗時は更新を見落としたまま進まず、原因と未実施を報告する。Python/外部アクセス不能時はGitHub connector等で現行SHA・全文を直接取得する。GitHubのSHA確認とAIの実際の理解は別ゲート。Pythonが動く常駐ランナーのない通常チャットで自動起動する保証はない。

### 全Playbook共通：目的と背景の継承（2026-10-31採用）

利用者に情報・結果を提示する場合、また調査・制作・引継ぎ指示を他のAIへ渡す場合、**【目的】1文 → 【背景】2〜3行（対象／狙い／位置づけ）→【必須条件】→【結果・検収】** を先頭近くの基本契約とする。各Skillは [AD&C本体の背景契約](https://github.com/Yosio-DMZ-C/AI-DODAI-Continuity/blob/main/docs/PROJECT_EXECUTION_STANDARD.md) を継承する。案件背景は個人KBのProject/Area Context等を実取得し、背景情報を受け手に読める形で渡す。リンクのみで代用せず、背景が不明なら `BACKGROUND_MISSING`、未確認を事実に変えない。

**固定済みの表・JSON・短文出力・厳密な最後の3行を変更しない。** その場合の背景は上流コンテキスト／形式が許す説明文で保持し、出力制約を優先する。背景の文章を動画・画像・公式テキストに無断挿入しない。非公開の個人事情は公開リポジトリへ転載しない。実際に別AIが読み理解したかは独立検収する。

### 新規導入時の共有Skill発見・記憶ゲート（2026-11-03／不具合再発防止案）

**観測された失敗**：新規AIで個人KB構築後、`50_skills` が空で共有カタログ未確認のまま登山相談に通常検索を適用。指摘後にPlaybookを発見した。個人KB構築の完了は、共有Skillの発見・適用の成功を意味しない。

**インストール時の必須検査**（個人KBを作るAIが実行）：
1. AD&C本体の導入指示書に従って個人KBを作成し、既存の保存・読戻し検収を終える。次に本共有READMEの「自然な依頼からのSkill選択」と `catalog.json` を実取得し、対象Skillの実在・状態・最新版URLを確認する。正式配布 `items` が0件でも、利用者採用の試用索引を「存在しない」と解釈しない。
2. 個人KBの `50_skills` または現行規則で指定された索引に、**共有Skillの入口リンク（コピー本文ではない）**を最小登録する。個人KBへの書込みは当該KBの現行書込手順と本人の承認境界に従う。登録不可なら未設定を明示し、導入成功とSkill発見成功を区別する。
3. AIのメモリ／継続指示が利用可能で、本人が保存を認めた場合だけ、次の短いルールを登録し、次の会話で実際に参照できるか確認する。メモリを直接操作できないAIは、コピー用文面を本人へ渡し、保存・自動適用をPASSにしない。
4. 初回の自然な依頼を模した試験（例：「来週、大台ヶ原で景色の良い登山ルートを」）で、一般検索**前**に共有ルーティング表→該当 `SKILL.md` 全文・版→個人優先手順を確認できるか検証する。山歩きなら最初の検索はYAMAP限定。通常検索先行ならFAILとし、リンク／記憶／起動指示を補修して再試験する。
5. 継続運用で参照不能・404・旧版・手順の詰まりがあれば、**共有README／カタログを再取得して最新版へ追従**する。利用者の許可なく公開GitHubや個人KBを自動更新せず、正本変更と単なる参照更新を区別する。

**継続指示／メモリの推奨文（本人が保存を許可した場合）**：

> 私はAD&Cを利用しています。相談を受けたら、一般検索や回答の前に、共有KBの現行README（https://github.com/Yosio-DMZ-C/AD-C-Shared-Knowledge）と自然文ルーティングを確認し、該当するPlaybookがあればSKILL.md全文と版を取得してその検索順序・安全ゲートを優先してください。個人KBに優先設定があれば確認してください。手順やリンクで詰まったら共有KBの最新版を再取得し、解決できない場合は未実施と理由を報告してください。未確認の手順を実施済みと称さないでください。

**判定の区別**：インストール本体PASS／共有入口登録PASS／継続指示保存PASS／新チャット自発発見PASS／実案件でのPlaybook適用PASSは別。メモリ保存だけでは実行保証にならない。共有READMEは自動的に新AIへ注入されないため、初回の導入指示書にも同じ起動ゲートを置く必要がある。

## AD&Cの理念との関係

**どんな玄人も、専門外では素人だ。** AD&C（AI-DODAI & Continuity）は、分野の玄人が当然知っている基本知識・手順・判断基準を共有できる形で整え、AIが利用者の状況に応じて案内することを目指します。**玄人の「当たり前」はAIが案内。人間は、その先の判断に集中する。**

人間の判断を置き換えたり、誰もが専門家になれると約束したりするものではありません。出典・反論・適用条件・更新状況を示し、重要な選択と承認は本人に残します。正式配布カタログのActive項目は現在0件ですが、山歩き・チャット引継ぎの試用項目は2件あります。理念全体の実装・効果が検証済みという意味ではありません。

## 何をしようとしているか

一から大量の情報を調べなくても、主要な主張、支持・反対の理由、未解決点、関連する専門家の実際の見解へ到達できる比較資料を育てます。答え・勝者・推奨行動の提示は必須にしません。個人差と科学的知識の更新を前提に、異論や判断が分かれる条件を残します。

- 確立した知見だけでなく、有力な仮説も根拠・不確実性・リスクを区別して扱う。
- 人気や投稿数を正しさとせず、出典の質・独立性・反証・適用条件を確認する。
- 主張ごとに専門家の公開発言・論文を紐付ける。発信者、監修者、相談先を区別し、必要時だけ本人に合う候補を検討する。
- 誤りは訂正し、重大な問題は撤回する。古い版を利用している人にも追跡可能な記録を残す。
- 最終的な選択は本人が行い、結果を保証しない。妥当な判断過程と偶然の成功を区別する。
