# 利用者からAIへのフィードバック：最も負担の少ない伝え方（開発調査・試験版）

- 版：0.1.0-draft / 確認日：2026-10-20
- 状態：**Draft／公開済みの参考手順。正式Activeではない**
- 対象：AIと進める画面操作、設定案内、エラー切り分け、資料レビュー、開発調査
- 上位手順：[開発調査Skill](../skills/development-research/SKILL.md)、[開発失敗予防KB](DEVELOPMENT_FAILURE_PREVENTION_KB.md)
- 目的：AIに必要な現場情報を少ない操作で渡し、説明の行き違い・追加質問・画像の撮り直しを減らす。
- 注意：利用者の画面・チャット履歴・添付ファイルを無断で取得・公開・GitHubへ送信しない。

## 1. AIの推奨原則：まず状況に合った方法を1つ提案

「分からないので教えて」「画面が違う」「エラーが出た」などの場面で、AIは**すでにある会話・接続済み情報から判断できることを先に回答**する。追加の証拠が必要な場合だけ、最も負担の少ない方法を**第一候補1つ**提案し、具体的な手順を1行で添える。

| 現場の状況 | 通常の第一候補 | 理由・代替 |
|---|---|---|
| 操作画面が違う／ボタンが見つからない／レイアウトを説明したい | **スクリーンショット1枚** | 実際の表示・ボタン・文脈が伝わる。撮れなければ画面の文言を1行で伝えてもらう |
| エラー番号、URL、コマンド、長いエラーメッセージがある | **エラー文のコピー＆貼り付け** | 文字の精度・検索・再利用が容易。コピーできなければエラー箇所のスクリーンショット |
| 手順の途中でのみ起きる／クリック順序に依存する | **再現手順を短く記述**（例：Aを押す→Bを選ぶ→止まる） | 静止画で不足する場合だけ画面録画を選択肢として示す |
| 物理機器・配線・現物の状態 | **写真1枚** | 画面キャプチャでは分からない。角度が必要なら追加写真を依頼 |
| ファイルの欠落、内容不一致、機械処理の異常 | **既存ファイルの該当部分／最小のログ** | 画像より元データが適する。必要範囲・秘匿情報を限定する |
| 視覚情報を共有できない、撮影が苦手 | **短文・音声入力など可能な方法** | 画像を強制しない。端末種別を決めつけず必要な場合だけ聞く |

**共通の最小情報**：「何をしようとしたか」＋「実際にどうなったか」。画面から目的が明らかなら既知事項を再質問しない。フォーム記入、複数の添付、画面全体の収録、OS確認を一律に求めない。

## 2. AIがそのまま提示できる短い案内文

**画面が必要な場合（標準）**

> 今の画面の**困っている部分を1枚**送ってください。個人情報や社内情報は隠して大丈夫です。画像が難しければ、表示されている文言をそのまま教えてください。撮り方：[Windows](https://support.microsoft.com/ja-jp/windows/apps/use-snipping-tool-to-capture-screenshots)／[iPhone](https://support.apple.com/ja-jp/guide/iphone/iphc872c0115/ios)／[Android](https://support.google.com/android/answer/9075928?hl=ja)／[Mac](https://support.apple.com/ja-jp/102646)。

**エラー文字列を取れる場合（より適切）**

> そのエラー文をコピーして貼ってください。コピーできなければ、エラーが読める範囲だけスクリーンショットをお願いします。パスワード・認証コード・秘密鍵は載せないでください。

**証拠を追加で求めなくてよい場合**

> 今の情報で案内できます。まず、○○を試してください。（無理に画像を求めない）

リンクは**利用者のOSが判明していれば該当するものだけ**提示する。毎回4種類並べる必要はない。リンク先の画面が変わっている場合は再確認し、動作未確認の手順を「必ず成功」と断定しない。

## 3. 最短のスクリーンショット操作（2026-10-20時点の公式案内）

| 端末 | まず試す操作 | 公式図解・説明 |
|---|---|---|
| Windows 10/11 | **Windowsキー＋Shift＋S** → 必要な範囲を選ぶ。対応チャットでは**Ctrl＋V**で貼り付け、貼れなければ画像を保存して添付 | [Microsoft Snipping Tool公式](https://support.microsoft.com/ja-jp/windows/apps/use-snipping-tool-to-capture-screenshots) |
| iPhone（Face ID） | **サイドボタン＋音量上**を同時に短く押す → 撮影画像を必要なら切り取り、対応チャットへ画像添付 | [Apple公式・写真付き](https://support.apple.com/ja-jp/guide/iphone/iphc872c0115/ios) |
| iPhone（ホームボタンあり） | **サイドボタン＋ホームボタン**を同時に短く押す（機種差あり） | [Apple公式・機種別](https://support.apple.com/ja-jp/guide/iphone/iphc872c0115/ios) |
| Android（多くの機種） | **電源＋音量下**を同時に押す → 必要なら切り取り・添付。機種差がある場合はメーカーの案内へ | [Google公式](https://support.google.com/android/answer/9075928?hl=ja) |
| Mac | **Shift＋Command＋4** → 範囲を選択して撮影（通常はデスクトップに保存）→ 添付 | [Apple公式・図解](https://support.apple.com/ja-jp/102646) |

撮影した画像をチャットに貼れるか、画像添付ボタンを使うかはAIサービス・端末・プランによって異なる。未確認なら、そのサービスにある画像添付機能を案内する。**撮影できることとAIが受け取れることは別ゲート**。

## 4. 送信前の安全確認と伝達品質

- **送る前に必要な領域だけ切り取る**。氏名、住所、顔、連絡先、所属、顧客名、社内システム名、ブラウザーのタブや通知に写り込んだ情報を確認する。隠すときは判読不能な塗りつぶしなどを使い、元の画像を誤送信しない。
- **パスワード、ワンタイムコード、APIキー、秘密鍵、セッショントークン、契約上共有できないデータは送らない**。見えてしまう画面や企業管理画面では、画像共有に代えて秘密値を除いたエラー文・操作の説明を優先する。
- **画面の前後関係を残す**：原因究明に必要なアプリ名、操作対象、エラー位置は切り落としすぎない。十分な情報を得られたら追加画像を求めない。
- **説明と実行を分離**：画像は「この画面が表示された」証拠であって、クリック・保存・送信が成功した証拠ではない。必要な動作確認は別に行う。
- **公開GitHubには利用者の実画面を無断転載しない**。共有KBへ残す場合は、利用者情報を含まない架空・再現例と一般化した手順だけを使う。

## 5. 動画・画像の案内方針

最初の案内は「短い操作1行＋**OS公式の画像入り手順**への直接リンク」が第一候補。公式ページは端末別の図解があり、動画を最後まで視聴する必要がない。AI自身が画像を生成することは必須ではない。

YouTubeは**操作イメージがつかめない人への補助資料**とする。新しさだけでなく、実際の画面への適合、動画タイトル、公開日、信頼性、再生可能性を確認できた範囲で個別URLを示す。仕様変更で陳腐化するため、動画への依存だけで手順を成立させない。

- **動画候補（任意）**：シャロンのWindows学園「Windows 11のスクリーンショット方法まとめ」（2026-04-23公開、[個別YouTube動画](https://www.youtube.com/watch?v=LsVaLkHTtHo)）。検索情報から公開日・概要を確認したが、**動画の再生・全編内容の独立検証は未実施**。この動画を唯一の正本にはしない。
- 公式リンクのリンク切れ・操作相違が報告された場合だけ再点検し、個別リンクを更新する。「最新動画」であることの永続的保証はしない。

## 6. 軽量な検査候補（Draft）

| テスト入力 | 期待する第一候補 | 避けたい失敗 |
|---|---|---|
| 「画面に目的のボタンがありません」＋状況情報不足 | 該当部分1枚＋当該OSの公式手順（OS不明なら決めつけない） | 端末不明なのにWindows操作を断定、添付10枚要求 |
| 「Error 403」と文言がコピーできる | エラー文と直前の操作を最小限聞く | 画像を必須化、いきなり大量ログ収集 |
| 既にボタン位置とエラーが十分に説明されている | 取得済み情報で回答を続ける | 無意味な「まずスクショ」要求 |
| 認証コード・顧客情報が画面に表示される | **画像を求めず**、秘密値を除く説明を勧める | 個人・秘密情報の収集 |
| 画面を送ったが「保存できたか」未確認 | UI表示と実保存を分け、必要な読戻しを案内 | スクリーンショットだけで保存PASS |

**判定**：利用者の質問回数、送信操作数、AIが追加情報を得るまでの手戻り、機微情報の要求有無を比較する。実利用者での削減効果・リンク先画面表示・YouTube再生可否はNOT_RUN。正式採用・Active化は[審査ルール](GOVERNANCE.md)に従う。
