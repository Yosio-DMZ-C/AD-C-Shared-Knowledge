# 金字塔的な概念の横断索引 — 設計案（Draft）

- **位置付け**：共有KBの分野別知識から、他の分野でも発想の転換に役立ち得る歴史的な重要概念を見つけるための索引。正式なカードデッキ、実行指示、推奨プレイブックではない。
- **目的**：利用者の相談分野に閉じず、人類が各分野で築いた重要な概念から、問題の**構造が似ている**別分野の知見を探す。その場の依頼を尊重したまま「高さ・広さ・深さ」のうち特に**広さ**を補助する。
- **状態**：提案段階。初期例は選定候補であり、専門家レビュー・全分野の選定・実際の対話試験は未実施。
- **既存契約との関係**：[基本設計](ARCHITECTURE.md) の `domain_id` と [主張比較資料](../templates/CLAIM_MAP_TEMPLATE.md)／[手順書](../templates/PLAYBOOK_TEMPLATE.md) の本文・出典を参照する。**現時点で `supported_kinds`、`catalog.json`、Core、Active、分野メニューの仕様を増やさない**。

## 1. 採録するもの／しないもの

「金字塔的」は人気ランキングや絶対的な正しさの認定ではない。元の分野で、**従来の問題の捉え方・方法・理論体系・制度を大きく変えた**ことを出典付きで説明できる概念を候補にする。「世界初」「史上最高」などの評価は、根拠がなければ断定しない。異論、歴史的修正、適用範囲の限界を明記する。

採録では、（a）歴史的な意義と一次資料・信頼できる研究史への参照、（b）要点を短く表現できること、（c）他分野への類推で使えそうな**抽象構造**、（d）その類推が成立しない条件、の4点を検討する。候補数・各分野の割当枚数にノルマを設けず、分野間の件数を無理に揃えない。

引用先の主張や専門的な論争を、この短い索引だけで確定させない。深掘りが必要なら既存の `claim_map` を参照または別工程で制作する。具体的な行動を勧める場合だけ `playbook` の別審査を適用する。

## 3. 各概念の最小記録（将来の索引項目）

新DBを作らず、まずは本書のようなMarkdownの一覧から開始できる。件数が増えた場合だけJSON化・検索索引化を検討する。

|記録欄|意味|
|---|---|
|`concept_id`、名称、`source_domain_id`|固定の概念ID、分野、別名。複数分野にまたがる場合も識別子を乱立させない|
|歴史的な転換点・採録理由|何を変えたと評価されるか。支持する出典と異論を含む|
|抽象構造・関連分野タグ|別の問題との**構造の類似**を探すための索引語|
|適用可能性の条件・破綻条件|表面的な連想・過剰な一般化を防ぐ|
|参照元とレビュー| `source_id` 等の出典、関連 `claim_map`／`playbook` ID、確認日、作成・確認者、Draft／Reviewed等の状態|

単なる発想候補と、出典を確認した知識を区別する。必要な出典・レビューが欠けるものをActive相当として配信しない。

## 4. 対話で「カード」として使う場合（将来案・未実装）

- **基本は現在の依頼を遂行する**。カードは回答必須要素にしない。利用者に概念を覚えさせたり、レベル1〜10で採点したりしない。
- 長く同じ仮説で停滞し、新しい情報・試験結果が増えないとき、AIが**異分野の概念を試しに参照**することはできる。以前の会話内容・失敗した方法をまず再利用し、無駄な再調査をしない。
- 「約5往復」は利用者との雑談で挙がった**試験上の感覚値**であり、固定トリガー・必須表示・時間制限ではない。会話が進んでいればカードを出さず、同じ誤解を反復するならカードより先に誤解の是正を優先する。
- 概念の選択には関連性や偶発的な着想を用いてもよいが、**ランダムだからといってユーザーへ出さない**。問題構造・仮定・限界を確認し、使えそうな場合だけ自然な一言を添える。ひらめきがなければ何も差し込まない。
- 利用者本人・提出先・組織内の裁量と理解を尊重し、依頼内の改善と仕事そのものの再設計を分離する。公開、送信、業務改革の提案を勝手に実施しない。
- コンテクスト汚染・反復誤解が続くときは、カードを繰り返すより**確認済みの事実・未解決事項だけを短く引き継ぐ新チャット案**を検討する。知識・権限・ツール不足はチャット切替では解決しない。

## 5. 後から調べる効果・採否条件

初期段階は公開済み情報の採録理由のレビューのみ。対話への組込みは、同じ架空相談について「通常回答」対「関連概念を条件付きで探す回答」を比較し、**有用な新仮説の発見、元の依頼の達成、余分な説明・質問、人間の理解、誤った類推、計算・時間負荷**を評価する。未検証の成功例を効果保証としない。

**不採用条件**：意味の薄い概念の押し付け、会話の停滞増加、本人の仕事上の不利益、過去と同じ示唆の繰返し、採録・維持コストが利点を上回る場合。通常の開発調査Skill・既存KB優先の原則を置き換えない。

**実施状況**：本設計文書と索引の候補例のみ。正式採録、概念の歴史的出典検証、AIへの配信、ランダム選択、カードUI、比較実験、他AIへの適用、継続的な更新担当者の確保はすべて **NOT_RUN**。正式な採用・拡張は既存の[更新・審査・撤回](GOVERNANCE.md)によって別途判断する。
