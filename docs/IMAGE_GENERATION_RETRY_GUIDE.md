# 画像生成：初回は簡潔に、失敗が続けば手法を再選択（補助ガイド／Draft）

- 日付：2026-10-31
- 位置づけ：画像生成全般の**任意の判断補助**。正式Active Skillや自動発動機構ではない。
- 適用：画像生成・既存画像の編集・動画用画像・サムネイルの制作相談。依頼が単純なら手順を露出させず通常どおり実行する。
- 上位：利用者の今回の指定、実取得した案件の採用条件、[AD&C共通実行標準](https://github.com/Yosio-DMZ-C/AI-DODAI-Continuity/blob/main/docs/PROJECT_EXECUTION_STANDARD.md)。動画サムネイルの具体的な制作工程は[動画Skill配下のサムネイルPlaybook](../skills/video-production-setup/THUMBNAIL_PRODUCTION.md)を優先する。

## 【目的】と【背景】

**目的**：画像生成の創造性を妨げずに、反復失敗が続いた場合だけ成果物の作り方を見直せるようにする。

**背景（共有できる一般形）**
- 対象：生成画像・編集画像・動画用の視覚素材。
- 狙い：初回の速さを保ちながら、同じ失敗を繰り返して利用者の時間を浪費しない。
- 位置づけ：Python-firstを義務化する規則ではなく、結果と制約に応じた方式の提案。

案件の実行時は、確認済みの対象／訴求目的／役割の2〜3行を案件Contextから継承する。読めなければ `BACKGROUND_MISSING`。背景は生成指示に必要な範囲で渡すが、画像内に印字する文字ではない。

## 初回の扱いと見直しの合図

1. **最初は素直に1案**：現在の依頼にある目的・必要な背景・必須条件に従い、手元の画像生成機能で制作する。特別な理由がない限り、複雑なPython処理・新規ツール・大量のプロンプト候補を先に作らない。
2. **例外は「既定の固定条件」**：公式素材の原形維持、文字の完全一致、厳密寸法、正規の個別Runbookが指定済みなら、初回からそれを守れる工程を選ぶ。「素で作る」を口実に、採用済みの合成・検査手順を省略しない。
3. **最初の修正**：指摘箇所だけを再生成・編集。成功部分・採用済み候補は保持し、何を変えたかを記録する。
4. **同種の失敗が重なる場合**（目安：修正2回、ただし固定条件の逸脱や成果物破壊は1回でもよい）：さらに同じ再生成を重ねる前に目的と失敗の型を確認し、**利用者に短く手法の見直しを提案**する。回数を機械的な強制停止条件にしない。本人が通常方式の継続を望む場合は、安全な範囲で継続する。
5. **見直し候補を絞る**：背景の再確認／過去の良好な画像の参照／レイアウト制約の先決め／文字・ロゴ・人物原画の非生成合成／Python等での寸法・文字・SHA・合成保証。全部を一律に適用しない。画風や構図の改善だけなら生成AIによる再提案が先でもよい。

利用者への短い案内例：「同じ部分の修正が続いています。生成の試行を増やすより、背景・確定文字・公式素材を分けて仕上げる方法もあります。次はその方式で試しますか？」

## 取り違えを防ぐ実行点検

- **入力契約**：目的／背景（対象・狙い・位置づけ）／必須文面／公式素材と権利・採用版／禁止条件／サイズ／今回任せる創作範囲を分ける。過去作品を参照するときは出典と採用状態を区別する。
- **ツールへの実引渡し**：READMEを読んだ・正しいプロンプトを文章に出したことと、**実際に画像生成へ渡した指示**の一致は別。実指示と生成結果を照合できる場合のみPASS。確認できない場合はNOT_RUN。
- **生成と非生成を区別**：描画対象から公式ロゴ・正式人物原画・厳密な日本語文面を外す必要がある案件では、生成は背景・演出に限定し、原本素材の合成と正確な組版を別工程で実施する。**最終合成物を再び画像生成で描き直さない**（正規素材保証が失われるため）。一般の自由なイラストでは分離を強制しない。
- **由来の保存**：再利用・厳密検査が必要な案件だけ、生成画像・公式素材原本・合成前後の名称／版／可能ならSHA-256／採用・未採用・候補を既存の案件記録に残す。ハッシュ一致だけで視覚の正しさは証明できない。
- **受入検収の分離**：①固定条件の忠実性、②目的に対する訴求力・読みやすさ、③実行工程の適合、④ファイル形式・解像度・実体保存、⑤指定された場合の本人の採否、を混同しない。証拠のない工程はNOT_RUN、ユーザーが作品を気に入った事実を機械PASSの代わりにしない。
- **途中で良案が出たら**：失敗した工程の記録を残しながら、良好な候補を破棄せず保全。安全な範囲で必要工程だけやり直す。実行できない工程を「別工程」で終わらせず具体的な阻害要因と再開地点を残す。

## 根拠と限界

2026-10-31のMUSEサムネイル実験報告では、背景を読んでも生成指示へ継承されない例、非生成合成後の描き直し、作品評価と工程評価の不一致を確認。B方式では有望な候補が出たが、比較条件が混在しており**B方式の優位性は未確定**。本ガイドはその実務上の失敗予防を一般化した暫定提案であり、画像生成サービスやAIモデル間の効果を実証した標準ではない。

**検収状態**：文書作成・相互参照はGitで検証する。独立AIの初見適用・実際の生成品質改善・手戻り削減は `NOT_RUN` のまま。
