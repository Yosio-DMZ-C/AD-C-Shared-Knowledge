# 更新・審査・撤回

## 役割と初期運用

リポジトリ所有者を初期の管理窓口としますが、専門資格や領域レビュー能力を推定しません。領域レビュアーは分野・確認範囲・利益相反を明示し、参加承諾後に登録します。まだ登録済みの専門レビュアーはいません。

通常の変更はPull Requestで提案し、管理担当が範囲とkindを整理、レビュー担当が該当ゲートを検査、リリース担当が結果を確認します。claim_mapは専門家の承認を一律必須にせず、AIによる別パスの原文照合・反論探索と管理担当の掲載判断でも審査可能です。その場合はAI支援レビューと明記し、人間の専門監修や独立専門家レビューと表示しません。正確に紹介できない主張は保留・未確認表示または専門レビューへ回します。

playbookは行動推奨のゲートを追加し、著者以外の確認と、高リスクの具体的行動には関連領域の適格な人間のレビューを必須にします。未確保ならDraftまたはInReviewに留めます。主張の掲載と推奨の承認を混同しません。

## 状態の遷移

|現在|移行先|必要条件|
|---|---|---|
|Draft|InReview|対象、出典、主張、リスク、評価ケースを記入|
|InReview|Reviewed|kindに適用する掲載ゲート、playbookなら追加推奨ゲートがPASS|
|Reviewed|Active|配布条件・ライセンス・確認期限・manifestが揃い、リリース担当が承認|
|Active|Disputed|重大な異論・根拠変更・適用問題を記録。既定の行動提案から除外|
|Active / Disputed|Retracted|重大な誤り・危険・権利問題。理由・影響版・代替を通知記録|
|Disputed|InReview|訂正または追加根拠による再審査|
|任意の非撤回状態|Archived|置換・終了。後継と理由を残す|

Retractedの旧版をActiveに戻しません。再公開には新しい版と審査を要します。履歴は追跡可能にしますが、秘密情報や権利侵害物は公開履歴の保全より除去対応を優先し、機微な本文を再掲しない通知だけを残します。

## 必須ゲート

作業開始時に、対象版・用途・必須検査・合格条件・方法・証拠保存先を定義します。

1. kind、問い、調査範囲・検索日・選定基準・未取得範囲を明示。playbookでは対象と対象外、行動・停止条件、必要な承認を追加。
2. 重要な主張と出典を対応。原文、AI要約、推論、事例、仮説を区別。
3. 因果関係と関連、対象集団、反証、限界、利益相反、独立性を確認。
4. claim_mapでは要約の忠実性、反対意見の取り落とし、根拠の重さ、専門家の発言との対応を評価。playbookでは重大な失敗ケース、境界条件、情報不足、必要な専門レビューを追加。
5. 権利・引用範囲・個人情報・再同定リスクを確認。
6. ID、JSON、参照、版、hash、適用期限を確認。表示前提の文書は表示も確認。
7. レビュー者・日時・結果・根拠を残し、公開対象と保存後の内容を照合。

必須FAIL・NOT_RUNは完成品提出を止めます。実行できない検査をN/Aに変えません。N/Aには適用外の理由、WARNには影響と処置を残し、合格条件に関わる未解決WARNは保留します。CIが未導入でも必要な検査は手動で行い、証拠を残します。

## 異論と緊急訂正

多数決や知名度では決めません。独立した根拠、適用条件、影響の大きさで判断し、少数意見も根拠があれば残します。対象テーマの見解が割れていること自体は比較資料の欠陥ではありません。資料がその相違を忠実に表現できればclaim_mapはActiveにできます。資料自身の要約・選定・出典に重大な未解決問題がある場合にDisputedとし、条件が異なる主張は分離して記録します。

重大な安全上の問題が疑われた場合、管理担当は通常レビューに先立って既定配布を停止し、影響ID・版範囲・理由・時点を記録できます。削除してなかったことにはせず、その後に領域レビューを行います。監視や応答時間の保証は現段階ではありません。

確認期限を過ぎた項目は原文を残しても、既定の行動提案から除外します。期限を延長するだけの更新は禁止し、再確認した根拠を記録します。外部情報の更新頻度と危険性に応じて期限を定めます。

## 版と証拠

- 主張比較資料とプレイブックはMAJOR.MINOR.PATCH。対象・行動・安全条件の互換性を壊す変更はMAJOR、互換追加はMINOR、意味を変えない修正はPATCH。
- 文書版、スキーマ版、カタログ版は別管理。公開済みの版を同じ番号で上書きしない。
- 安全上の訂正は版番号だけで伝えず、影響版範囲を持つ撤回・訂正記録を付ける。
- 公開済みレビューは対象コミットと結びつける。本文変更後は影響する検査を再実施する。

## 参加者が増えたときの合意形成（PLURALITY研究を参照する条件付き設計案）

> **状態：2026-10-18の研究・対話に基づく将来の検討入口。正式な採決制度・自動化・外部サービス導入ではない。** 小規模運用は従来どおりGitHub Issues / Discussions / Pull Requestsと人間の審査を使い、参加や議論の方式を利用者へ強制しない。

### 何が起きたら再検討するか

次のような**実際の運営上の支障**が確認されたとき、管理担当が理由・議題・影響範囲をGitHub Issueに短く記録し、通常のGitHub機能で対処可能かを先に検討する。参加人数や経過日数だけを強制的な発動条件にはしない。

- 複数の立場がかみ合わず、同じ論争や採否を繰り返している。
- 活発な少数者に議論が偏り、異論・無回答・少数意見が実質的に見えない。
- 「誰が何を決めたか」「なぜ採否を分けたか」が追えない、またはPR・審査の優先順位に公正さの疑義がある。
- 専門家、標準的な情報源、推奨される方法の選定が、利益相反や正当性の問題を伴う。

**基本の切り分け**：共有KBの**事実・根拠・専門的定石の妥当性**は資料と適切なレビューで検査する。一方、**運営上の優先順位・手続・参加方式**は当事者の意向・負担・正当性を含めて合意形成する。人気投票で科学的正しさ、専門資格、推奨先や安全条件を確定しない。

### 必要になった場合の小さな進め方

1. **いつもはGitHubだけ**：提案→反対意見と根拠→人間のレビュー→判断理由→PRと版履歴を残す。GitHubアカウントを持たない閲覧者のため、結論は専門用語を抑えた要約も用意する。
2. **意見の構造が見えなくなった場合**：任意の短期試験として[Polis](https://pol.is/home)を検討し、主張への賛否・意見群・横断する共通点・少数意見を把握する。自己選択・多重回答・モデレーション・非参加者の存在を明示し、「参加者の意見」から「利用者全体の意思」を推定しない。
3. **正式な共同体の採決・委任が必要になった場合**：[Gov4Git](https://github.com/gov4git/gov4git)等の外付け方式を比較する。本人確認、投票権・異議申立て、トークン権限、運営費、障害時の手動復旧を別途検証。PolisもGov4GitもGitHub正本を置き換えず、自動マージ・Active化に直結しない。
4. **外部連携が本当に反復負担になる場合のみ**、既存Issue IDと外部の議題URL、集計版、採否理由を結ぶ最小の参照記録から検討する。新DB・自前投票基盤は既定では作らない。Private KBや個人の投票履歴を公開GitHubへ転記しない。

### 人間が理解できる公開審議（構想・未実装）

- 多数の意見を人間が追いきれない場合、**AIが代表的な「立場」を整理**して対比し、各立場の根拠・論理上の弱点・反例・合意できる部分を示す方式を検討する。AIは**実在参加者や専門家本人を装わず**、入力資料の範囲、要約の不確かさ、少数・未参加の立場を明示する。
- 背景で根拠の強さ・論理的整合性を評価する構想はあるが、数値や「AI採点」が採否の正当性を保証するわけではない。評価基準・使った資料・反論・人間が訂正する方法を説明可能にする。人間の能力、立場や価値そのものを採点しない。
- **約3か月に1回の公開対話・再審査**は、論点を人間が理解できる速度にするための**将来の試験仮説**であり、現時点で周期を設定しない。参加者の負担と実際の議題で見直す。重大な誤情報や安全・権利上の緊急訂正は定期審議を待たず、前節の撤回・訂正手順を優先する。
- 人間に渡す要約は、争点、主要な立場、共通点、少数意見、採否理由、未解決点、次の判断を区別する。反対者に再反論・訂正・異議の機会を残し、意思決定の権限と責任は人間の管理・審査担当に置く。

**専門家・参照先の取扱い**：将来、一般の人に「玄人の最低限の定石」や参照すべき標準資料、専門家を案内する場合も、資料の発行主体・更新日・対象・争点・利益相反・選定理由を示す。AIや参加者の支持を専門家による監修と誤表示しない。紹介候補の妥当性を人数だけで確定しない。

**根拠と検討境界**：2026-10-18調査メモ「AD&C × PLURALITY / Polis / Gov4Git：参加と合意形成の外部基盤に関する研究メモ」（Research Draft、非公開Library）と、同日の利用者・調査担当の対話を元にした検討入口。[『PLURALITY』](https://www.plurality.net/) / [公開編集リポジトリ](https://github.com/pluralitybook/plurality) / [Polis](https://github.com/compdemocracy/polis) / [Gov4Git](https://github.com/gov4git/gov4git)。元レポートの全内容を転載せず、一般化した設計条件だけを記す。今回の**外部サービス接続、投票、実際の集計、AI代表討論、運用試験はすべてNOT_RUN**。新しい採用判断には、対象議題・参加者・権限・公開範囲・評価方法を改めて確認する。

## 現在未設定の制御

ブランチ保護、必須承認、CI、CODEOWNERS、撤回通知サービスは未設定です。この文書は運用契約であり、GitHubが機械的に強制しているという意味ではありません。担当者と権限を確認してから設定し、設定後に実際の拒否・通過を試験します。
