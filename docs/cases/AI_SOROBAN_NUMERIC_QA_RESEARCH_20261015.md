# 開発調査ケース：先行技術の採用とAI数値出力の検査

- 日付：2026-10-15
- 状態：Draft。研究記録・採用候補。自動検査の実装／独立レビュー／Active化はNOT_RUN
- 目的：先行サービスを使わず計算Workerを作った経験から、先行研究優先と数値検算の不足を再評価する
- 公開用に個人限定Site URL、プラグインID、非公開ログは記載しない

## 結論
1. 開発前に**既存の公開API・ライブラリ・Skill・実装例**を先に調べ、使用できるなら採用し、不足だけを作る。既存サービスの機能、利用中AIのアクセス能力、実動作の成否は区別する。
2. AIの文章中の数字を全部検算するのではなく、重要な**導出計算値**（合計、差額、割合、商と余り、日付演算等）を優先して、生成時に決定的な計算ツールを使い、出力チェックで式・入力値・単位・丸め・実際の応答を照合する。転載統計は出典照合、型番・日付・IDは原則算術検算しない。
3. 不一致ならFAILとし、利用可能な計算機で**修正と再検査**。利用できない環境は計算機の利用案内とNOT_RUNにとどめ、自前の推算を「ツールで検証済み」としない。機密値を第三者の公開計算URLへ無断送信しない。

## 先行技術の精度比較
- [math.js公式 REST API](https://api.mathjs.org/) はGET/POSTの一般計算API。無料サービスは1日最大10,000件、1評価10秒以内と公式案内。
- [math.js Numbers](https://mathjs.org/docs/datatypes/numbers.html)：既定のNumber型には浮動小数点精度上限がある。
- [math.js BigInts](https://mathjs.org/docs/datatypes/bigints.html)：ライブラリは大整数を厳密に計算可能。従って**「AIそろばんの方がmath.jsより高精度」という一般化は誤り**。
- [math.js BigNumbers](https://mathjs.org/docs/datatypes/bignumbers.html) と [設定](https://mathjs.org/docs/core/configuration.html)：高精度小数対応。BigNumber精度の既定は64桁（変更可能）。通常のREST APIの表示精度指定だけで演算過程の精度を保証するものではない。
- AIそろばんの利点：入力を40桁以内の整数文字列へ限定し、JS BigIntへ渡すため、暗黙のNumber丸めを避けやすい。一方、小数・単位・関数は対象外。

## 試験記録（2026-10-15）
- ChatGPT通常チャットのSites版 `calculate` ツールで、40桁×40桁の実応答 `{"value":"12193263113702179522618503273386678859448712086533622923332237463801111263526900"}` を取得。入力：`1234567890123456789012345678901234567890` × `9876543210987654321098765432109876543210`。当チャットで暗算による補完なし。
- `10000000000000000001 - 10000000000000000000` → Sites版ツールの応答 `{"value":"1"}`。ローカルNode.js `Number` の同じ式は `0`、`BigInt` は `1`。**比較対象はNumberとBigIntであり、公開math.js APIの実測比較ではない**。
- math.js REST APIへの大整数試験：NOT_RUN（本環境でDNS失敗等、URL取得不可）。無料APIが同条件で誤答するとは判断しない。
- 出力チェック工程の自動化：NOT_RUN。今回の文書は仕様案であり品質効果の実測ではない。
