# 動画制作の一工程：サムネイル作成Playbook（Draft v0.1／2026-10-31）

- **位置づけ**：[動画制作・初期設定Skill](SKILL.md)配下の**実制作サブ手順**。一般動画のサムネイルにも、明示的に依頼された単独サムネイルにも使えるが、別の並行動画Runbookや正式Active配布項目を増やすものではない。
- **目的**：動画の内容と訴求が一致し、正式素材を壊さず、縮小しても伝わるサムネイルを制作・検収する。
- **優先順位**：今回の明示依頼 → **実取得した案件・シリーズの採用済み個別Runbook／素材仕様** → 本Playbookの不足補完 → 低リスクな裁量。案件固有の画風・文面・寸法・完成定義を公開一般形で上書きしない。
- **出所**：MUSE制作実験の最終判断（2026-10-31）。A/Cで画像生成指示の伝達逸脱、Dで合成後の再描画、Bで有望候補だが比較優位未確定、先行成功例で人間評価とPython実行が不一致。方式の優位性は未検証。

## 1. 目的・背景をツールまで運ぶ

制作依頼の最初に、**【目的】1文 →【背景】2〜3行→【必須条件】→【今回の創作範囲】**をそろえる。

- **対象**：正式な動画名・主題・配信先。固有名詞が略称や他サービスと紛れる場合は分類・提供元・誤読しやすい点も短く示す。
- **狙い**：視聴者のどんな理解・感情・行動を変える画像か。単なるサービス説明ではなく、この動画で伝える成果。
- **位置づけ**：シリーズのどの作品か／誰が主役か／説明より体験を重視する等、実際の構図が変わる優先事項。

**元の案件正本から文章を継承し、画像生成ツールに実際に渡す指示へ含める**。内部READMEを読んだこと、プロンプトを表示したことと、ツールへ渡した実際の指示は別。実渡しを照合できないなら `NOT_RUN`。背景不明なら `BACKGROUND_MISSING`。背景の文章をそのままサムネイルに印字しない。

## 2. 初回は簡潔に、必要な案件だけ3層分離

1. **固定条件が少ない単独画像**：最初は画像生成で自由な1案を作り、目的・可読性を確認。単純な生成にPython工程を最初から要求しない。[画像生成の手法見直しガイド](../../docs/IMAGE_GENERATION_RETRY_GUIDE.md)を参照。
2. **公式ロゴ・登録済みキャラクター・完全一致の日本語文面などを守る案件**：初回から、採用済み手順に従って「背景を生成／公式素材を非生成で合成／文字を組版」の3層分離を使う。AD&Cの個別制作は個人KBの現行動画Runbook・素材仕様に従い、この方式と役割分離を保持する。「まず素で」を理由に緩めない。
3. **実験で既に良い候補がある**：以前の画像は元画像・出所・採用状態を確認して比較参照できる。過去の候補が優れて見えても、その制作工程が全PASSだったとは推定しない。

### 固定条件がある場合の3層

| 層 | 主な担当 | 正しい結果／禁止事項 |
|---|---|---|
| 1 背景・演出 | 画像生成AI | 訴求目的に合う構図・光・余白・情緒。**指示で禁止された**人物・文字・ロゴは描かせない |
| 2 公式素材 | 非生成合成（例：画像編集・Python） | 出所を確認した原画・ロゴを**縦横比固定**で配置。再描画・顔の改変・ブランド形状の改変はしない |
| 3 確定文字 | 組版（例：画像編集・Python） | 確定文面と字句・引用符・句読点の完全一致。日本語フォント・可読性・安全余白を確認 |

**仕上がった3層合成結果を画像生成AIで再描画しない**。どうしても表現の修正が必要なら背景層だけ再生成し、元の公式素材・確定文字を再合成する。自由な画像制作に常にこの3層を課すものではない。

## 3. 実行順（動画の一部として完了まで）

1. **制作単位を固定**：本編、独立日次クリップ、Shorts、単独画像のどれか。動画タイトル・採用台本／新規台本・視聴者・媒体・確定コピーを照合する。動画表紙（PPT）とサムネイルは別の成果物であり、サムネイル依頼にPPT表紙の演出ルールを無断流用しない。
2. **必要物を実取得**：採用済み原稿・動画、公式素材の原本と権利、サイズ・画角、ロゴ、人物原画、本文の確定文面、既存良案。見つからない原本を似た素材や生成ロゴで代用しない。取得できない必須物だけ `NOT_RUN`、他の安全な構成検討は継続。
3. **制作指示を分離**：目的・背景・固定文面・禁止事項・創作範囲を記載し、必要な背景を**実際の生成指示**へ渡す。A/C型の「正しい指示を作ったのに別指示を渡した」事故を防ぐ。
4. **初回1候補を生成**：条件に応じて単純生成または背景層生成。訴求力を優先するが、公式素材を模倣した再描画はしない。
5. **必要なら合成・組版**：非生成処理で正式素材と文字を適用。画像の幅・高さ、色、縦横比、文字のスペルと安全余白を確認。透明原画がない場合は継承版に依存しない候補を検討し、正式素材必須なら止める。
6. **完成候補の検収**：下の二軸を別々に検査。人間の目視採否が条件なら確認までCandidate。良案は工程が部分失敗しても出所と状態付きで保持し、捨てない。
7. **動画へ接続**：案件で指定がある場合のみサムネイルを動画末尾へ指定秒数の静止画として付与し、非公開アップロードとカスタムサムネイルの設定へ進む。**AD&C個別案件での末尾1〜3秒・動画完成条件**は現行個人Runbookが決める。一般のオフライン動画／別SNSに一律の末尾貼付やYouTube登録を強制しない。投稿・公開・有料機能・外部送信は本人許可と権限が確認できる場合のみ実行する。
8. **保存と引継ぎ**：元素材・生成層・最終画像・必要時の動画MP4・採用状態・QA・再開地点を現行案件の成果物に紐付ける。可能ならファイルSHA-256を照合し、後からの混入・取り違えを検出する。

## 4. 品質ゲート：作品と工程を分離

| ゲート | PASS条件 | 注意 |
|---|---|---|
| 忠実性 | サイズ・画角・文字・ロゴ原本・人物原画・禁止条件・動画内容との対応が現物に一致 | 文面の一致は機械、構図の意味は目視も必要。実ファイル未取得ならNOT_RUN |
| 訴求力 | 縮小時にも視認可能、どんな価値・変化がある動画かが伝わる | 可能なら本人の目視採否。AIの自己評価だけで人間評価PASSにしない |
| 指示伝達 | 実際の生成ツール入力と、承認された目的・背景・条件の対応を確認 | README読了・プロンプト出力だけではPASSではない |
| 工程・由来 | 必要な非生成合成、元画像・生成層・最終画像の別保存・対応の確認 | 表現が良好でも工程未実施はPASSにしない。SHAだけで内容評価PASSにしない |
| 動画との結合 | 必要時の末尾フレーム・動画デコード・カスタムサムネイル設定・ID読戻し | その媒体で不要なら理由付きN/A。未アップロードはNOT_RUN |

動画の完成条件がサムネイルを含む案件では、**サムネイルの忠実性・訴求力が両方PASSになるまで「動画完成」と宣言しない**。一般の単独サムネイル制作も、人間検収が指定された場合は採否前に完成を断定しない。

## 5. 反復失敗への対応と報告

- 修正2回程度／同じ誤字や素材の描き直し／背景の脱落／生成指示の置換などが続く場合、原因を **目的理解・指示伝達・画像生成・素材合成・文字組版・検収** のどこかに切り分ける。
- 原因が生成ではなく指示伝達やPython合成なら、画像を再生成する前にその工程だけ修正する。合成後の再生成はしない。単純生成で限界なら3層分離や参照画像活用を短く提案する。
- **最低限の記録**：今回の対象／目的・背景3行／生成へ実際に渡した指示（閲覧可能なら）／作成画像と版／採用素材／修正回数と原因／人間待ちの地点／忠実性・訴求力・工程の各判定。既存Project・制作記録を使い、新しい台帳や自動ジョブを増やさない。
- MUSE実験のB方式を標準化・優位と断定せず、A〜Dの結果は条件の違いと証拠を添えて比較する。

この文章は制作方法の**Draft**。既存採用のAD&C個別Runbookを置換せず、共有動画Skillの実制作分岐として参照する。実行型手順の新規重要改訂では[共通実行標準§6.3.2〜§6.3.3](https://github.com/Yosio-DMZ-C/AI-DODAI-Continuity/blob/main/docs/PROJECT_EXECUTION_STANDARD.md)のQ1〜Q4で独立解釈・実制作・利用者受入を検査する。文書整合だけPASSでも、実画像生成・他AI再現・動画完成は `NOT_RUN`。
