## 1. 起動時の分岐：新しい基準が必要なときだけ

1. 対象シリーズ・媒体・読者・目的・望む印象・繰り返し利用予定を把握。必要な既存Project／Areaの現行採用内容のみ取得する。
2. **採用済みスタイル・制作キットがあれば再利用を優先**。本人の明示的な刷新、新シリーズ、実際に不足している要素だけ最小限に構築する。採用済みの原画・ロゴ・固定文面・位置は勝手に再生成・移動しない。
   - AD&Cの**一般向け説明図／ブログ挿絵／通常PPTX**には、案件固有の採用済みスタイルがない場合だけ[既存の共通グラフィックスタイル v1.0](../../assets/ADNC_COMMON_GRAPHIC_STYLE_v1.0.md)と実見本・原本を再利用候補とし、**既に決まっている作風をStyle Bootstrapで作り直さない**。動画・サムネイル・MUSE CASE Aの個別採用仕様には適用を強制しない。
3. 新規・大きな刷新のときだけ、次の「代表作1件」へ進む。最初から大量のテンプレート・一括アイコン生成・汎用JSON仕様書・新台帳を作らない。権限内で可逆な制作を進め、採用判断や新たな公開・課金等だけ本人承認を守る。

## 2. 代表作からスタイルを取り出す最短工程

### A｜実際に良い代表作品を1件制作

シリーズの次の制作にもっとも役立つ、代表的な1枚／1場面／短い記事の一部を**実際に表示できる候補**にする。ブログならアイキャッチと本文図解の典型、動画なら表紙・代表カット、資料なら本文の代表図解などから今回必要な範囲を選ぶ。文字の意味、画面の見せ方、余白、視線誘導、読者の理解を優先。比較案は必要なときだけ少数にし、**採用判断がない候補を正式採用済みにしない**。

人間の視覚的な理解・印象を助けるアイコンや矢印・図解は積極的に検討する。ただし全ページへの強制はしない。[公式SVGの検索と権利確認は既存素材表D](../video-production-setup/PRODUCTION_ASSETS_GENERAL_SPEC_v0.1.md)を使い、見本画像の切り抜きを編集用SVG原本として流用しない。

### B｜採用見本からスタイルと実素材を抽出

作品そのもの、編集可能な原本、表示画像、必要な素材の取得先と出典を**既存のArea／Project・制作キットの保管先**へ記録し、そのそばに短いスタイルカードを置く。中央共通データベースや新たな必須JSONスキーマは作らない。

| 再利用する基準（固定候補） | 作品や媒体に合わせて自由に変えるもの |
| --- | --- |
| 実取得できる見本のURL／既存ID・版・採用状態 | 作品タイトル、訴求、話の流れ、主張 |
| ブランド色・文字の雰囲気・アイコン系列・線幅・余白の目安 | 縦横比、情報量、構図、背景表現 |
| 公式ロゴ・人物・画像・編集できる図形・利用権 | その作品に合った図解、表情、配置 |
| **人間が確定・固定した文字や領域** | **変更してよい箇所と創造する箇所** |

**スタイルの共有と、画素／配置の完全一致は違う**。ブログ本文・PPT・サムネイルにはそれぞれ適した画面がある。現物から確認できないサイズ・色・書体は推測で正式値とせず unknown とする。スタイルカードは「目的・見本の実体・使う素材・固定と可変・出典・利用条件」が分かれば足りる。JSONは、現在の作品で既に役立つ場合に限り**任意の派生形式**。JSON→PPTX／画像の完成済み自動生成機構を仮定しない。

### C｜編集可能な原本と画像制作を適材適所で使い分け

- **編集可能性・人間の後修正が重要**：PPTX・DOCX・SVGなど実際に編集できる原本を保管し、PNG・PDF・Web用画像は必要なときに派生出力する。**文字・カード・矢印を後で直したい図解にはPPTX方式が有力**。詳しい制作手順は[既存PPTX制作](../video-production-setup/SKILL.md)／[文書・ブログ制作](../document-authoring/SKILL.md)を使う。
- **造形・表現の自由が重要**：画像生成や適法な画像素材で背景・装飾・画風を創る。確定した人物・公式ロゴ・日本語文言は必要に応じて**原本から非生成合成**し、採用見本と派生画像を区別する。
- **併用も可能だが義務ではない**：同じ色・素材・作風を共有しつつ、画像版とPPTX版は媒体の目的に合わせて変えてよい。両方を常に作る、画素を完全一致させる、全部をPowerPoint経由にする、などは要求しない。

**専門正本を変更しない**：動画本編・サムネイルはシリーズArea→現行個別Runbook→採用素材定義の経路を優先。MUSE CASE A、二段階制作、Q2/Q3、SHADOW、音声方式、公式素材、固定文字などを本Skillで改訂しない。ブログ冒頭の「この記事のまとめ」・本文図解などの規則は[文書制作Playbook](../document-authoring/SKILL.md)が正本。図解・アイコンの種類やライセンスは[共通素材表D](../video-production-setup/PRODUCTION_ASSETS_GENERAL_SPEC_v0.1.md)に委ね、ここで複製しない。

### D｜別題材で1件再利用して通常制作へ戻る

1件だけ別の題材で、保存した見本・スタイルカード・実素材を**取得→使用→保存→表示**できるか確認。旧作品の文章や絵をそのままコピーすることは成功としない。同じ雰囲気を維持しつつ新しい内容に合うかを確認し、問題があった部分だけ最小差分で修正。独立AI・別アプリで実行していなければそれらは NOT_RUN。新たな無限ループ・全案件検査を作らず通常制作へ移る。

**採用済み見本への参照（2026-11-11）**：最初の代表成果として本人が正式採用した[AD&C共通グラフィックスタイル v1.0](../../assets/ADNC_COMMON_GRAPHIC_STYLE_v1.0.md)を確認。そこには実取得・実表示済みのPPTX／JSON／Library画像、公開記事3図への取得経路と未検証範囲を記録した。新規にStyle Bootstrapを毎回起動せず、通常制作はこの見本の再利用を優先する。下記の「報告ベース」の記述は**本Playbook作成時点の履歴**であり今回の現物検証とは区別。

## 3. 完成と検収・今回の着想事例

**成果物**：①実際の代表作（採用候補／本人採用済みを区別）、②必要な編集可能原本と実素材、③既存の保存先に接続した短いスタイルカード、④必要な媒体用派生画像、⑤人間向け日本語の「固定部分／変えてよい部分／次の制作方法」。今回使わない原本・媒体・出力方式は要求しない。

**区別する状態**：REPORT_ONLY（別担当からの報告のみ）／FETCHED（実ファイル取得済み）／RENDERED（実表示済み）／ADOPTED（本人の採用済み）／REUSE_PASS（異なる題材で実使用済み）。一つの達成から残りを自動推定しない。公開・有料利用・機密送信・不可逆な原本上書きは既存の許可境界を守る。

**発想の根拠（報告ベース／本Playbook作成担当による現物未取得）**：2026-11-11に共有された別担当の報告では、ブログに挿絵3枚を追加し、編集可能なPPTX4枚とデザイン仕様JSON試作品を作ったという。記事の保存後再取得・PPTX再読込と描画試験は報告者の主張であり、**ここでは記事・画像3枚・PPTX4枚・JSONの実体を取得していない**。本実装での現物検証は REPORT_ONLY、当該JSONは試作であって媒体横断の正式生成エンジンではない。KOF企画は今後の実使用機会であり、成功済みとは記さない。

## 設計上の重要点（本人採用・2026-11-11）

- **採用理由**：良い代表作品を先に実際に制作し、そこからスタイルと使える素材を抽出すると、次回以降の再説明・素材再作成を減らせる可能性がある。品質・時間削減効果の実測は別判定。
- **変更禁止**：既存の採用済みロゴ・原画・台本・構図・文字・CASE A・専門Runbook・権利条件を、この初期工程を理由に再生成・上書きしない。
- **避ける失敗**：抽象JSONだけで完成扱いしない。見本1件と再利用1件で実物を確かめ、毎回の制作に重い初期工程を課さない。
