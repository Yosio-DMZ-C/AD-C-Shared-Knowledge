## 目的・適用条件
古いソフトで作成された読めない文書・表・図・アーカイブを、**原本を保持したまま、現在のAIや人間が利用できるテキスト・表・画像・PDF等へ変換し、内容と欠損を検査して保管**する。研究・デジタルアーカイブ・旧業務資料・写真媒体などに適用する。拡張子だけで正体を決めない。

利用者の自然文例：「昔の一太郎が読めない」「昔のPCの文書を救出」「.jtdを一括テキスト化」「CD-RWから取り出した資料を復元」「旧型式データをPythonで変換」「文字化けを直してAIで検索したい」。

## 実行方式：小さなアジャイルループ
**観測 → 最小試行 → 実測 → 必要な修正 → 次のファイル**。問題がなければ1回で終了。調査のためだけの追加台帳・承認・無限ループを設けない。

1. **対象を特定**：保存場所・拡張子・サイズ・先頭バイト（マジック）・元ソフト／版・作成時期・複数サンプルを観測。権限・提供元条件・取り扱う個人情報を確認。初めての形式は代表1〜2件だけ試す。
2. **原本保全**：原本を書き換えない。読取専用の複製を作り、元ファイル名・大きさ・SHA-256・出典を記録。傷んだ物理媒体は大量アクセスや修復書込みを先行しない。必要ならイメージ複製を優先。未知のEXE・マクロは実行しない。
3. **方法を探索**：利用可能な既存AIツール／OS／ソフト → 公式ベンダーのビューアと対応版 → メンテされているOSS／GitHub・PyPI・文献 → 書式解析の順。検索語には拡張子、元ソフト名、version、read/convert/extract、OLE/CFB、unicode/encoding、archiveを併用。ライセンス、更新日、OS、依存、入出力、実績を確認。**第三者のオンライン変換サイトへの機密・個人データアップロードを既定にしない**。
4. **一案を実行**：可能ならローカルPython等の再利用可能な既存手段。バッチ化前に代表ファイルの複製を読み、テキストの先頭・末尾、表、数字、日本語、改行、図を確認。複数出力が必要ならテキスト（AI検索）＋PDF/画像（見た目の照合）を用途別に生成。
5. **差分・検収**：変換結果の存在・ファイル数・空でないこと・文字化け・欠落・表列ずれ・ページ欠損・プレビューを実測。原本のSHA不変も再確認。成功は `TEXT_PASS`・`LAYOUT_PASS`・`TABLE_PASS`・`IMAGES_PASS` 等、必要な目的に分ける。検査していない項目は `NOT_RUN`。抽出可能と完全な復元は別。
6. **記録・再利用**：原形式・入力例（公開側は匿名化）・ツールとURL/版・使ったコマンド・出力と検収・失敗原因・修正だけを既存案件KBへ追記。ツールが動けば次の同系統ファイルへ展開し、失敗した箇所のみ修正。未対応形式なら次善策へ進む。
7. **結果の出力・次の一手**：確認できた成果物、原本保全、未復元箇所、次に効く1操作を示す。無断の公開・削除・機密送信は行わない。

## 道具棚：確認済み／候補と使い方

### JTD（一太郎）— Pythonを先行
**実動済み（限定）**：1999年の `ＧＥＡＲスタッフマニュアル.jtd` と `ＧＥＡＲミーティング方式.jtd` の**コピー**を既存Python試作で読み取り、日本語本文を抽出（2026-11-16）。抽出前サイズ 34,816 / 20,480 bytes、抽出後 2,979 / 890文字。スタッフ文書は表に制御文字が混ざりレイアウト未保証。対象原本は非公開のためこの公開リポジトリに含めない。

- **同梱の読取専用Python最小抽出器**：[`tools/jtd_text_extract.py`](tools/jtd_text_extract.py)。Python 3、標準ライブラリのみ。JTDのOLE2/CFB `DocumentText` ストリームから文字を推定抽出する実験的な補助ツール（形式上の完全互換を保証しない）。従来の個別テキスト抽出に加え、オプションでJSSnapShot32の表示キャッシュから文字列を取得。表セル位置・計算式は未復元。
- 実行例（**複製だけ**を入力）：
  ```bash
  python tools/jtd_text_extract.py "/path/to/copy/sample.jtd"
  ```
  同じディレクトリに `sample.txt` (UTF-8) を生成する。出力先に同名の既存ファイルがあれば**上書きしない**。入力のJTD原本は変更しない。抽出結果の本文と原本表示を照合する。
- **上流Python候補**：[o2md（PyPI）](https://pypi.org/project/o2md/)／[GitHub](https://github.com/matsu582/o2md)。一太郎JTD→Markdown、表構造などの改善が必要なら候補。実行例 `python -m pip install o2md` の後、提供する `jtd2md` CLIの使い方を該当バージョンのREADMEで再確認。今回の制限環境ではpip取得できず**本体は未実行**。
- **公式描画・原本照合**：[JustSystems 一太郎ビューア](https://www.justsystems.com/jp/download/viewer/ichitaro/)（Windows）。旧版のJTDを画面表示できる場合は印刷→PDF、ページ・表・字形を確認。閲覧ソフトによるレイアウト復元は今回未試験。
- **他の解析候補**：[Tika-JTD](https://github.com/KHiyowa/Tika-JTD)（Apache Tika系、Java）／[ezpzfile-jtd](https://github.com/ezpzfile/ezpzfile-jtd)（Rust）。実データ互換性未検証。出典・READMEで最新版と実行方法を確認してから導入。

### 2026-11-16 公式ビューアとの比較で改善した会計表・スタッフ表
公式一太郎ビューアの表示画像を利用者が提供し、会計報告書の収入8,500円／支出8,180円／収支320円、年間収入22,525円／支出50,651円／差額-28,126円を検算。一太郎JTDの `DocumentText` だけでは会計表は取得できなかったが、埋込 `\x03EmbeddedPress` に `JSSnapShot32` 表示キャッシュが存在し、`--snapshot-text` により文字列の金額8,500・8,180・320・22,525・50,651を抽出できた。赤字の符号は公式画像と差額計算で確認した。**表セルや関数を機械復元したとは扱わない**。
```bash
python tools/jtd_text_extract.py --snapshot-text --enhance --inspect-embedded "原本コピー.jtd"
```
出力 `.snapshot.txt` は**表示内容の並びを近似した断片列**で、不要な描画コマンド・字体名や列結合が混在する。年度会計表や金額の正式な復元・自動集計には、公式アプリのPDFや画像との照合を要する。

スタッフマニュアルの `.tables.md` は、受付5行と設営3行について公式表示画像の3列（内容・時間帯・備考）と照合。時間割の3列（時刻・会員・参加者）は未構造化で、改行・セル結合・位置の完全再現は未検証。

**回帰試験**：当該機能追加後、1999〜2000年のJTDコピー29件で旧版の本文抽出結果が29/29一致。特に先行の非空26件に後退なし。別形式や異なる年代のJTDでの互換性・表示キャッシュの存在は未保証。

### 2026-11-16 実測：埋め込み三四郎ワークシートのセル番地を部分復旧（v1.0.3）
`ＧＥＡＲ会計報告書.jtd` **原本コピー1件**のOLE複合ファイル内 `Book` と `WorkSheet1/2/3` を検査。各ワークシートは `u16 record_type / u16 record_length` のTLV構造を持ち、`0x1000` レコード内の `row, col`（0起点）と型を実測で判別した。値の型 `2` は16bit整数、`5` は表示属性付きUTF-16LE文字、`20` は計算済みfloat64と未復号の式命令列。以下のコマンドでCSVとJSONを作成する。

```bash
python tools/jtd_text_extract.py --worksheet-cells --fallback "原本のコピー.jtd"
```

生成：`*.cells.csv`（表計算ソフトで確認）、`*.cells.json`（formula_hexを保管）。入力原本を変更せず、既存の同名出力ファイルを上書きしない。複数ファイルの場合は対象のコピーを個別に試す。

**公式ビューア画像と一致した検査値：**
- `WorkSheet1!C2 = 8500`（入力数値）、`C4 = 7680`、`D4 = 500`。
- `WorkSheet1!I2 = 8500`、`I4 = 8180`、`K3 = 320` は **数式セルの保存済み計算結果**。
- 本件の算術照合：8500−8180=320。ほかの年度合計（22525・50651）は別の埋込み表示キャッシュにあり、このワークシートからのセル位置を復元したと主張しない。
- 29件の既存JTDの本文抽出に対する回帰比較は **29/29一致**。

**重要な限界**：セル番地と保存済み計算結果は復元したが、**数式本文はまだ復号できていない**。数式領域は `formula_hex` として保全し、`formula_decoded=false` を出す。`=SUM(C2:H2)` 等の式を推測で自動出力しない。また元ファイルの全書式・結合セル・多段階参照・別版のワークシートとの互換性は未検証。現段階では部分復元として利用する。

### JSD（三四郎）／JHD（花子）
`.jtd` と同じ処理をかけない。三四郎表計算は**数式・セル・シートと値の違い**、花子図面は**線・文字・レイヤ・座標**を重視して別手段を調べる。花子ビューア：[公式配布案内](https://www.justsystems.com/jp/download/viewer/hanako/)（Windows対応版を必ず確認）。今回の原本では変換・完全性とも `NOT_RUN`。

### 旧Office・書庫・媒体・文字コード
- `.doc` / `.xls` 等：元形式と実データの互換を確認し、適合するOffice互換ソフト・変換器を複製で試す。OLE2はコンテナ形式であり中身の文書形式を保証しない。
- `.lzh`・ZIP：まずアーカイブ内部の一覧・テスト・名前文字コードを確認、解凍は複製と隔離先へ。パストラバーサル・実行形式・悪性マクロに注意。
- `Shift_JIS/CP932`・EUC-JP・UTF-8：元バイトを保持して候補文字コードで確認。エラーを `replace` した文字列は原文完全復元ではない。
- 光学媒体／故障ディスク：読取エラーがある場合は取り出し直しを繰り返す前に媒体状態・イメージ化の可否を確認。復旧操作・書込みは原媒体に実施しない。
