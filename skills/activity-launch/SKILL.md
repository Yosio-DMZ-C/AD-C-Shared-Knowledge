# 活動立ち上げ：動画制作から公開・改善まで（YouTube例／Draft）

## 目的と適用境界

完成した動画を一時ファイルのまま消失させず、サムネイル・チャンネル設定・公開情報・振返りとともに、一貫した作業単位として再利用する。YouTubeは例であり、他媒体では操作と仕様を再確認する。**新しい動画制作エンジンや自動投稿APIを作る指示ではない。**

組織利用では標準KB・権限・ブランド規程・公開承認・保存先規則を優先する。個人利用では、所有者が許可しアクセスできるストレージを使う。AIは公開・権限拡大・不可逆操作を所有者に代わって独断で実行しない。

既存のKB/ファイル管理/品質ゲートを再利用し、同じ内容の二重台帳を作らない。既存手順があれば流用し、不足分だけ補う。

## 入力

- 活動の名称、誰に何を伝えるか、公開者と決裁者、投稿先と所有アカウント
- 動画/PPT/原稿/音声等の素材と、作業版・正本・公開版の区分
- 公開範囲と組織制約、権利・本人同意・AI生成利用の条件
- 保存先（なければ選択候補）、予算、利用可能なサービス／権限
- 既存チャンネル等を使うか、新規作成が必要か

## 標準フロー

1. **制作・QA**：原稿、音声、映像を作り、再生時間・画音同期・表示・必要な権利を確認。動画の正本と編集可能なソースを区別して永続保存。
2. **サムネイル案を文章で3案**：視聴者向けのメッセージ、伝わる根拠、過大表示にならないかを添えて提示。通常は所有者の選択を待つ。**所有者が明示的に選択省略を許可した場合だけ推奨案を採用し、その旨を記録する。**
3. **サムネイル画像を生成・照合**：採用案に沿って作成し、タイトルとの整合、可読性、縦横比、誤記、著作権、保存完了と取得を確認。サムネイルと動画は別資産として管理。
4. **投稿先の用意**：既存チャンネルの利用可否を先に調べ、なければ所有者に作成手順を提示。チャンネル名／固有ハンドルの空きを確認し、プロフィール画像・バナー・説明・外部リンク・管理権限を設定。既存の個人チャンネル資産は無断変更しない。
5. **公開文面**：タイトル候補（原則3案）、最適案、概要欄、関連リンク、固定コメント、必要なら再生リストを用意。実装済み／試験中／将来構想と効果の実測を区別。宣伝のために確認不能な効能を断言しない。
6. **限定公開または非公開で試験**：動画アップロード、サムネイル、音声、字幕、リンク、視聴者側アクセス、端末別の表示、権利/AI開示設定を検査。サービスUIが異なる場合は現在の公式ヘルプで確認する。
7. **最終承認後に公開**：所有者が承認し、公開範囲を切替。外部公開操作に必要な権限・承認が取得できない場合は未実施と明記。
8. **公開ログ・改善**：公開URL/日時、動画とサムネイルのID・版・保存先、変更履歴、チェック結果、失敗・反応を記録。次回は差分更新やテンプレート再利用を優先。

## 品質ゲート（証拠と状態を分離）

| ゲート | 判定対象 | 未実施の扱い |
|---|---|---|
| ASSET | 正本の保存、再取得、ファイル照合 | NOT_RUN |
| VISUAL | 画面、文字、サムネイルの表示確認 | NOT_RUN |
| AUDIO | 音声の途切れ、音量差、映像同期 | NOT_RUN |
| RIGHTS | 利用素材の権利、本人同意、公開区分 | 未確認なら公開保留 |
| PLATFORM | 規約・サムネイル・AI開示・視聴者設定 | 未確認なら公開保留 |
| ACCESS | 限定公開の実URLを第三者視点で確認 | NOT_RUN |
| APPROVAL | 決裁権者の公開承認 | 未承認は未実施 |
| DELIVERY | 公開URLの実体と更新済み台帳の読戻し | NOT_RUN |

**表示成功≠保存成功≠公開成功≠受信側閲覧成功。** 未実行をPASSにしない。失敗時は再実行可能な工程から再開し、重複投稿・二重公開を避けるため最初に投稿済みURL・版を照合する。

## 最小成果物

- 制作物の正本リンク（ソース、動画、音声、画像）と版・更新日時
- サムネイル文案3件、採用案と選択者（または省略許可）
- チャンネル設定文面、動画タイトル/概要欄/固定コメント
- 検査表（PASS/FAIL/NOT_RUN/N/A）と未完了理由
- 公開後URL・日時と改善ログ（公開までは空欄のまま）

## プライバシー／共有KBへの移植

このSkillには個人所有アカウント、メールアドレス、APIキー、顔/肉声音源、非公開の個人KB等を載せない。個別事例と個人向け投稿本文は非公開プロジェクト保存先に置き、汎用原則・必要な検証項目のみ共有KBへ移す。

本書は**Draftの一般手順**であり、独立レビュアーの評価、実チャンネル作成、実動画公開、回帰試験はNOT_RUN。共有KBのActive登録やmainマージには既存GOVERNANCEの審査・承認を適用する。
