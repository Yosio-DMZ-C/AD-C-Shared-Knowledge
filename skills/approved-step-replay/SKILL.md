# 承認ステップ継承・局所改稿 Playbook

> **目的：** ユーザーが「いい」「これでOK」と認めた成果・工程を失わず、後からの一言修正を、完成品として自然な形で反映する。変更禁止の宣言だけで終わらず、**承認済みの直前工程までを再利用し、最後の編集工程だけを丁寧にやり直す**。

- ID: `approved-step-replay`
- 版: `v0.1.0-draft`（2026-11-04）
- 状態: **Draft／独立試験未実施／正式Active・配布未登録**。本書の作成やレビューは、他AIでの実行成功を意味しない。
- 対象: 画像・サムネイル・ポスター・写真コラージュ・スライド・Web画面・文書など、会話で段階的に作り込む成果物。
- 対象外: 白紙からの新規案で採用状態がない場合。既存の個別Runbook、公式素材、本人が指定した確定条件を上書きしない。

## 1. 背景・完了条件

**背景：** 一度認められた画像を次の修正でAIが丸ごと再描画したり、指定文字だけを雑に貼って文字組みが崩れたりすると、ユーザーは以前の判断を何度も言い直す必要がある。ユーザーの要求は「変更点以外を凍結」だけではなく、**採用した制作過程を踏襲して、修正箇所を正しく再組版すること**である。

**完了条件：** (1) 正しい採用元が選ばれ、(2) 指示された意味・位置・スタイルで変更が入り、(3) その箇所は文字量に応じて自然にレイアウトし直され、(4) 変更許可範囲以外の採用要素が保持され、(5) 実物の比較と保存後の読戻しが行われる。

本書では「ユーザーの操作負担を減らす」を重視する。未確認の選択肢を毎回質問しない。一般的な組版や整列は制作側が担い、重大な衝突や変更不能に限って確認する。

## 2. 最重要の区別：確定したもの／再実行するもの

### 2.1 採用範囲を意味で管理する

- 「いい」「これでOK」「2枚目がいい」「この構成で」は、**その発言が指す成果物・部位・条件**を採用した証拠として扱う。前のAI案が新しい日時で再登場しても、採用済み最新版にはしない。
- 「2枚目の構成」「写真の配置」「上の見出し」は部位指定。「これをベースに」は提示された実画像／ファイル指定を優先。採用語を、無関係な制作案全体の一括承認に拡大しない。
- 後の修正で採用されたのは**修正した部分のみ**。指示されなかった部分は、その時点の採用状態を継承する。
- 明示的に添付された画像や採用ファイルがあれば、会話中の最新生成物よりその**現物と識別子**を優先する。推測で「たぶんこの画像」として進めない。

### 2.2 二種類の固定を分ける

1. **成果固定（what）**：人物・写真・構図・コピー・色・書体・看板・装飾など、本人が保持したい完成状態。
2. **工程固定（how）**：写真補正→コラージュ配置→装飾→文字レイヤー→書き出し等の再現可能な順序、素材、パラメータ。

成果固定だけでは「文字を足したが中心がずれた」が起こる。工程固定だけでは「前工程をAIで再生成して写真まで変わった」が起こる。**両方を守る**。

## 3. 実行手順（人間に追加操作を要求しない標準経路）

### Step 0 — 今回の変更指示を1文に限定

「何を」「どこへ」「何を維持して」変えるか抽出。例：「中央の『明日からオープン!!』の前に日付を入れる。採用済みの黒い墨文字・白フチ・中央揃え、他写真と上部見出しは保持」。元画像にない理由・装飾・コピーを善意で補足しない。

### Step 1 — 直近の**明示的に採用された元成果物**を特定

- 当該添付・採用版の実ファイル／画像を取得し、ファイルID／パス、寸法、ハッシュまたは確実な参照を記録。
- 制作状態が層別データなら、元写真、レイヤー、指定文面、フォント、位置、背景補正値、書出し条件を確認。
- 現物を取得できない場合は、別の似た画像を原本扱いせず、取得不能を明記。編集可能な範囲だけ作業する。

### Step 2 — 採用工程の最後の安全なチェックポイントを選ぶ

工程列を `S0 元素材 → S1 補正 → S2 配置 → S3 装飾 → S4 上段文字 → S5 中央文字 → S6 出力` とする。

- 変更対象がS5なら、**S4までの採用状態を復元または再利用**し、S5だけ作り直してS6を書き出す。
- `S4` の層別ファイルや背景のみ画像があるなら、それを最優先。決定的な処理（座標・拡縮・色補正など）は、採用パラメータで再実行できる。
- 過去工程に生成AIの非決定的な処理がある場合、**生成AIへ再び描かせてS0〜S4を「再現」しない**。承認済み画像・レイヤーをチェックポイントとしてそのまま使う。
- 中央文字を焼き込んだ単一PNGしかない場合は、同一画像の**限定領域だけ**で旧文字の除去と新しい文字の合成を行う。以前の文字を背景ごと消せないなら検収NG／要素材。全画面の再生成を代替経路としない。

### Step 3 — 指示箇所だけ再設計・再組版

- 新しい文の文字数、行数、改行位置、字間、行間、既定の見出し対本文比率を計測する。
- **中央揃えは文字ブロック全体の中心座標を維持して再計算**。既存文字列の左端に単純追加しない。短い補足行を入れる場合も、まとまり全体の視覚中心と安全余白を見直す。
- フォント・墨文字・白フチ等の**採用書式を再利用**。黒白の指定を金・赤等へ変更しない。「日付だけ」は日付以外の文言も勝手に書き換えない。
- 改稿領域内でサイズ、折返し、上下間隔、背景とのコントラストを調整することは、指定変更を成立させるための**局所裁量**として許可。ただし写真、採用済み見出し、その他の要素には波及させない。
- 領域内で読める組版が不可能な場合は、領域を勝手に拡張せず、最小限の代案（たとえば日付を一行小さく）を示す。

### Step 4 — 合成して外側を一切動かさない

- `editable_mask`（変更できる矩形または形状）と `protected_mask`（その他全部）を明示する。局所合成可能な環境では変更マスクの外を元画像から**画素そのままコピー**する。
- 見た目を変えないと言いながら画像生成AIへ全面編集を頼むことは、保全方法として認めない。生成AIは未確定の新規背景や選択肢制作には使えても、確定画素の再現保証には使わない。
- 変更部分の視覚設計（書体選びや改行など）にはAIの判断を活用し、固定部分の配置・文字列・公式素材の合成には決定的なツールを用いる。

### Step 5 — 形式検査＋目視検査

**必須検査は別々に記録する：**

| 検査 | PASS条件 |
|---|---|
| 採用元 | 明示的に指定／承認された原本が一致し、別版へのすり替えなし |
| 指示反映 | 文言・日付・誤字・追加場所・書式が指定どおり |
| 局所レイアウト | 日付と見出しが中央に自然に収まり、文字間・行間・白フチ・余白・視認性が保たれる |
| 変更範囲 | マスク外の画素差ゼロ（PNG等の同一ピクセル系で検査可能な場合）。他形式では非変更要素の構造差分と目視確認を実施し、未検査をPASSとしない |
| 既存内容保持 | 上部見出し、写真、看板、人物、料理、下段の文言等の採用条件に変更なし |
| 受渡し | 画像を実書出し→存在・寸法→再読込。必要なら編集元も保全 |

`PASS`／`FAIL`／`NOT_RUN`（理由つき）を維持。画素差のPASSと作品として自然かどうかのPASSは別。**「変更箇所以外は完全一致」と述べるのは実際に差分検査した場合だけ。** JPGの再圧縮等で厳密比較できなければ、その限界を説明。

### Step 6 — 戻しと再提出

- 失敗した箇所だけ直し、承認済みの上流工程は再変更しない。標準再試行は1回を目安とし、同じ原因の全画像再生成を繰り返さない。
- 修正後の画像を提示し、**「変えた部分」と「保持した部分」**を一〜二文で説明。検査できなかった事実を隠さない。
- 新しい採用が出たら次版のチェックポイントとして保全し、次回は**そこから**再開する。

## 4. 画像編集時の技術分岐（制作環境ごと）

| 利用可能な素材 | 採用経路 | してはいけないこと |
|---|---|---|
| PPTX・PSD・SVG等の編集可能なレイヤー | 指定テキスト層を書き換え、当該グループだけ中心揃えして書出し | 他層の座標やマスターをついでに変える |
| 制作コード・再現可能なレシピ＋段階画像 | 採用済みチェックポイントを読み、最後のテキスト処理だけ実行 | 全工程を未固定の乱数／生成AIで走らせ直す |
| フラットPNGと修正領域が明瞭 | 文字部分を局所修復して非生成の文字を再合成し、領域外の差分を検査 | 「元と同じ」と指示した画像生成で全面描き直す |
| 編集元なし、文字を除去すると背景を壊す | 局所修復を試すか、編集可能元の取得を依頼。無理ならFAIL／NOT_RUN | 見た目が似た別構図を納品し、成功と宣言 |

**非画像への適用例：** 文章なら承認済み段落をそのまま保持して指定段落だけ推敲。スライドなら既存マスターと固定図形を保持して当該テキストボックスだけ再組版。Webなら承認済みHTML／CSS・コンポーネント構造を保全し、指定コンポーネントだけ変更してスクリーンショット比較。

## 5. 回帰試験（初見の別AIが同じ仕事をできるか）

| ID | 指示・前提 | 合格条件 |
|---|---|---|
| T1 | 採用済みコラージュへ「日付を『明日から』の前に」 | 日付が追加され、中央文字群が再センタリングされ、他領域の画素が一致 |
| T2 | 「左上の『お待たせしました』は残す」 | 上段文字が変更・再描画されず、中央だけ改稿 |
| T3 | 「黒い墨文字、白フチ」採用後に小修正 | 黒／白の指定を守り、金色や赤の独自装飾を加えない |
| T4 | 「2枚目がいい」後に別の生成画像ができる | 最も新しい出力ではなく、指定された2枚目を原本として使う |
| T5 | 旧文字がフラット画像へ焼き込み済み、元レイヤーなし | 全画面再生成を禁止。局所修復できなければFAILとして説明 |
| T6 | 文字が長くなり既存ブロックをはみ出す | 文字領域内の改行・サイズ・余白を調整。他の素材を押し退けない |
| T7 | 「いいね」と画像の一要素だけ褒められた | 全画面の正式採用を勝手に推定しない。参照対象の範囲を記録 |
| T8 | 「日付だけ」の依頼なのに下部コピーもAIが変更 | FAIL。元へ戻して許された差分のみ再提出 |

**合格判定**：出力画像・文書等の実物、差分結果、再取得証跡が揃った試験のみPASS。Playbookの記述レビューは実動作試験を代替しない。試験素材は架空・公開可能なものを使用し、個人の実画像・店舗・会話内容を共有KBへ転載しない。

## 6. 次のAIへ渡す最小のチェックポイント

追加の管理DBを作らず、既存の作品Context／引継ぎ／成果物メタ情報へ以下の最小項目を残す。承認状態はユーザーの言葉と採用対象に紐づけ、**時刻順だけで最新版を選ばない**。

```yaml
project: "<作品ID>"
adopted_source:
  asset_id: "<実ファイルID／参照>"
  version: "<採用版>"
  sha256: "<取得できる場合>"
  dimensions: "<幅x高さなど>"
approved_stages: ["S0", "S1", "S2", "S3", "S4"]
approved_elements:
  - "<ユーザーが明示的に保持した構図・書式・文字>"
current_delta: "中央文字群へ日付を追加"
editable_region: "<座標／グループ／レイヤーID>"
editable_stage: "S5"
composition_rules: ["既定書式を維持", "文字群の中心座標を維持", "他領域は変更不可"]
source_assets: "<既存素材の参照。非公開情報は共有しない>"
checks:
  source_match: "PASS | FAIL | NOT_RUN"
  content: "PASS | FAIL | NOT_RUN"
  visual_alignment: "PASS | FAIL | NOT_RUN"
  outside_diff: "PASS | FAIL | NOT_RUN"
  readback: "PASS | FAIL | NOT_RUN"
next_step: "<未完了の一工程>"
```

## 7. 事例から得た禁止事項と判断の境界

- ユーザーが決めた上段の見出しを残すよう言ったのに、日時追加を理由に写真・配置・全体色・別のコピーまで作り直さない。
- 文字だけ追記したとしても、中央ブロックのバランスが崩れたら**仕事は未完**。変更範囲内で丁寧に再組版する。
- デザインを良くするための自由な創造性は、**まだ決めていない領域**にだけ使う。「もっとよくなる」は確定領域を壊す根拠にならない。
- ユーザーからの「違う」「そこは動かすな」は、単なる好みの不一致ではなく**工程選択の誤り**として原因を検証する。
- **既存の作品別Runbookと正式仕様が優先**。本Draftを他の全制作に一括適用、正式Active化、個人KBへの無断書込みはしない。

## 8. リリース判定と次工程

**本書の文書検収**：入口、採用元選択、チェックポイント再利用、局所再組版、禁止変更、差分・目視、失敗時の扱い、回帰試験の各記載を確認する。**実制作試験／独立AI試験はNOT_RUN**。採用前にT1〜T8のうち、まずT1・T2・T5・T6を隔離素材で実施し、承認済み領域の保持と局所センタリングを確認する。結果と採否を既存の開発正本へ紐づける。
