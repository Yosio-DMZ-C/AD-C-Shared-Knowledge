# AD&C｜ガイド・報告の統一HTML/PDF制作Playbook v0.1.1

<!-- ADNC-VISUAL-DOCS-20261121 -->
**採用範囲**：2026-11-21本人指示。人間向けガイドの体裁統一、および秘書・PJ・定例レポートとの視覚デザインの共通化。**標準Playbookに紐づく公開可能な人間用ガイドには本体裁を採用し、標準外の個人・外部制作者は任意参加**。**公開ガイド**と**非公開・テンポラリ報告**の公開／保存経路を混同しない。新しい承認ゲート・台帳・Taskを増やさない。

> 「完成形のない仕組みで、完成する仕事を増やす」。Gitは制作者のため。人間にはGitHubの上部UIを見せず、完成済みガイドか一時PDFを渡す。

改訂時だけ取得：理念 [共有KB README](../../README.md)、[Designer’s Note](../../templates/DESIGNER_NOTE.md)、[開発プラクティス](../../docs/DEVELOPMENT_WORKFLOW_PRACTICES.md)。通常のガイド利用者に読ませない。

## 0. 発動・既存専門Playbookとの境界

- 「人間向けガイドを作る・統一する・印刷する」→本Playbook。記事本文・機器固有の安全・画面操作は**当該専門Playbook／公式資料優先**。現在の3D/MCPガイド本文を機械的一括置換しない。
- 「秘書/PJ/定例を見やすく報告」→[既存HTMLレポート制作Playbook](../html-report/SKILL.md)と[既存Python生成器](../html-report/render_report.py)、[既存PDF変換器](../html-report/html_to_pdf.py)。入力は既存KB・業務正本から取得。**デザインだけ本Playbookと共有**し、報告正本・実行ロジック・集計分母は変更しない。
- 本人がHTML、PDF、編集可能な資料等を明示指定すれば、その形式を優先する。固定出力を専門Playbookが定めている場合も同様。

**ガイド制作の初手**：`guides/guide-layout-example.html` を作業コピーにし、必要な本文と `guides/assets/adnc-unified.css` を用意する。ローカルのブラウザーで狭幅（例：360px）を表示し、横スクロール・文字欠け・リンクを確認。PDFが必要なら下記「ガイドPDFの実行入口」を使い、実ファイルを開いて確認する。ブラウザーや変換器が使えない場合は未検査の項目を明示し、取得済み本文を渡す。公開操作は別。

## 1. 共通デザイン契約

- **視覚トークン**：濃紺 `#11243e`、文字 `#192d43`、青緑 `#087f7b`、リンク `#0b6d92`、白 `#ffffff`、背景 `#f6fafd`、区切り `#d2e5e9`。指定可能なら日本語は **Noto Sans JP**。不達時に字形を保証したとは記さない。
- **画面構造**：短い種別表示と表題 → この記事のまとめ／今回の要点 → 必要ならページ内目次 → 必要な準備 → 番号付き操作／カード → 問題時の復旧 → 完了の確認・次の一手。報告は従来の正本・件数・優先度・結果表示を維持し、「ガイドの章構成」を強制しない。
- **人に見せる情報**：初心者が読める短文、図は必要なときだけ、編集用のGit差分や内部パスは本文の主導線にしない。GitHubへの改善報告リンクは任意の参考リンクとして置いてよいが、読者の通常の閲覧には不要。
- **公式ブランド表示**：基本ガイドヘッダーに**既存のAD&C公式ロゴ（横組み）**を小さく置く。[ローカル同梱の公式ロゴ](../../guides/assets/adnc-official-logo.svg)は本人の登録済み原本 `ADNC_Logo_Compass_Wordmark_20261016.png`（原本SHA-256 `d09ae8275353270decb4c3367ebab6d485ae810ff5a5fed59883757794922319`）を**縮小・トリミングした画素を埋め込んだSVGラッパー**であり、生成AIで描き直したロゴではない。公開サイトは同梱素材を使用し、WordPress/Google Drive等へ実行時アクセスしない。表示サイズは**控えめな署名**として通常画面で幅約112px・スマホ幅約94px・印刷約92pxを上限の目安にし、ヘッダーの高さを圧迫しない。公式ロゴ原本の画素は変更せずCSSのみで縮小する。画像に代替文字を持たせ、原本取得不能な環境では文字の`AD&C`表示で代替し、業務を停止しない。社内ガイドに無断持込みしない。
- **実装CSS正本**：[共通CSS](../../guides/assets/adnc-unified.css)（公開ガイド用）。[完成見本](../../guides/guide-layout-example.html)・[ガイド一覧](../../guides/index.html)を最初の制作雛形として使用。既存レポートPythonは**同じ色トークンをHTMLに内部埋込み**し、CSS読込みのため外部にアクセスしない。
- モバイルは原則1列。読み順を保ち、長い日本語とリンクを折り返す。フォーカス表示、見出しの階層、画像代替文、必要な注意喚起を備える。大きな固定幅・見かけだけの操作ボタンを避ける。

## 2. 公開ガイド：Git原本、読者はWeb/PDF

1. **Git原本**：一般公開が認められたガイドの `.html`、共通CSS、必要な図・画像、編集履歴を本リポジトリ `guides/` 以下で管理。社内資料・認証情報・個人の報告データ・非公開URLを置かない。
2. **独立した閲覧画面**：読者のリンク先は、認可された静的ホスト上の**レンダリング済みHTML**とする。GitHub `blob`・`raw`は制作側の原本閲覧であり、人間用のHTML表示URLとして提示しない。GitHubのヘッダー・ナビ・ファイルツリーを読者に見せない。ただしガイド自身のページ内目次は残してよい。
3. **配置方式**：[公開ガイド専用GitHub Pagesワークフロー](../../.github/workflows/publish-human-guides.yml)は`guides/`内の**公開許可済みファイルだけを個別許可リストで選んで**サイト成果物へ複写し、`skills/`・`reports/`・`private/`・KB・一時ファイルを公開成果物へ含めない。通常のGit差分履歴はGitHubに残す。リポジトリのPagesソースを**GitHub Actions**として設定できる権限が必要。Pages URL・実表示は**公開後のブラウザーで初めて確定**する。 `has_pages=true` やworkflow存在だけで公開PASSとしない。
4. **ガイドPDF**：閲覧・印刷・持ち帰り用に同じHTMLから任意でA4縦PDFを生成。元HTML・CSSはGit原本。PDFをGit管理するかは本人・専門Playbookの明示判断。必要がなければPDF成果物は利用時の一時ファイルでよい。
5. **過去のガイド**：現行 `guides/3d-print/`・`guides/cloudflare/` の表記や動作を自動で一括変更しない。改訂時に、本文や採用済み図を壊さず**共通CSS・章構成を局所採用**する。

### 公開PR・標準／標準外の境界（本人採用 2026-11-21）

- **標準Playbookに紐づく公開可能な人間用ガイド**は、既定でGitの `guides/` からGitHub Pagesの完成HTMLとして公開する方向。公開前に機密情報／社内固有の操作／認証情報／無断転用素材を対象限定で確認する。ガイドの存在・PR受領だけで無条件公開しない。報告系の一時HTML/PDFは対象外。
- **GitHub PRは歓迎**。既存ガイドの更新・新ガイドの追加をPRで受け取り、内容・権利・現物表示・専門Playbookへの対応だけ確認して、通常の`main`へ反映する。新ガイドの公開は[明示許可リストのPagesワークフロー](../../.github/workflows/publish-human-guides.yml)にも対象HTMLと必要素材を追記。**PRを受け取ることと自動マージ／自動公開は別**。新しい台帳・承認制度は作らない。
- **標準外の個人・外部制作者は本体裁に従う義務なし**。合わせたいときは本PlaybookとCSS・完成見本を任意で再利用。作業そのものや本体の利用は統一体裁への参加を条件にしない。

### ガイドPDFの実行入口

```sh
python skills/html-report/html_to_pdf.py guides/guide-layout-example.html \
  --css-file guides/assets/adnc-unified.css --no-web-logo \
  --output /tmp/adnc-guide-example.pdf
```

- `--css-file` は**手元で実取得できるCSS**だけをPDF生成へ注入。Webから取得しない。PDF変換器はPlaywright/Chromiumを使用し、ネットワーク外部リクエストは遮断する。外部CSS参照だけを書いたHTMLをPDF化した場合に、スタイルが消える問題を避ける。
- 印刷ではA4縦、**単一列・上→下の読み順**、自然改ページ、文字選択、日本語字形、見出しの位置、リンクを確認。Web限定のページ目次・操作ボタン・コピー操作は印刷しない。 `details`はPDF化時に展開する。1ページ圧縮を強制しない。
- PDFは閲覧用。ボタンの動作、同意手続やフォーム入力は元HTMLまたは人間用操作案内へ戻す。

## 3. 非公開報告：**一時HTML → 一時PDF → その回の1リンク**

- 対象：秘書の日次、PJ、定例、巡回結果、機密を含み得る個人・社内報告。各正本・REPORT_TO・保存ルールはそのまま。
- **通常の出口**：既存の認可された業務正本を読取→権限内の一時領域で `render_report.py` 等によりHTML生成→ `html_to_pdf.py` で縦単一列PDF変換→**実際に生成済みのその回のPDFリンク1件を提示**。中間HTML・PNG・PDFを公開GitHub・Pages・第三者プレビュー・公開URL・恒久Driveへ自動保存しない。利用終了時の一時ファイル保持は実行環境の規則に従う。
- **一時PDFの公式ロゴ**：認可済みのローカル公式PNGがある場合は既存の[変換器](../html-report/html_to_pdf.py)の`--logo-file`を使ってヘッダーへ小さく配置。公開用の同梱SVGを現場の実行環境に強制配布せず、ロゴが取得不能なら既存の文字`AD&C`で継続する。報告を公開する理由にはしない。
- 読者が明示的にHTMLの操作画面を要求した場合は、本人の指示と認可範囲で別扱いにできる。通常報告の表示入口は**PDFのみ**。PDFにコピー・編集ボタンは残さない。
- PDF生成器の実在・権限・受取りリンクが確保できない場合は**通常の短いテキスト報告へ戻る**。未生成のPDFリンク・偽URLを作らない。閲覧用PDFを新しい業務正本としない。
- 秘書の従来の4択・一問一答・日次/月次処理、PJのWBS、定例の実行回ID、T015のUNKNOWN判定は変更しない。秘密を公開サンプルへ入れない。

## 4. 最小検収

| 対象 | 実確認の条件 |
|---|---|
| Git原本 | 変更前に現行版取得、改訂範囲だけ保存、Git読戻し・差分確認 |
| 共通体裁 | タイトル・要約・手順・警告・完了確認、狭い画面での縦読み。字形・図・リンクの実表示 |
| ガイドの公開先 | Pagesビルド成功、実URLの描画、GitHub UI非表示、公開範囲の確認。元リンクの表示だけではNOT_RUN |
| ガイドPDF | 実生成済ファイル、文字選択、A4縦・単一列・自然改ページ、必要なリンクと図、外部要求遮断 |
| 一時報告 | 正本IDと実績整合、外部公開なし、一時PDF 1リンク実存在・受取可能性、元業務処理を維持 |
| 未実証 | 現物が無ければNOT_RUN。ロゴ・外部フォントが取得できなくても安全な代替で継続 |

**今回の導入基準**：公開用CSS・ガイド一覧・完成見本・Pages配布ワークフロー・PDF変換器のローカルCSS指定がGit mainへ保存・読戻しできたことと、**実公開ページの完成**は別。Pages設定権限や実サイトへのアクセスが未確認ならNOT_RUNと記録する。秘書HTML→PDFの既存6ページ実証は、PJ・ガイドPDFの本番実証へ繰り上げない。

## 5. 結果の出力・次の一手

完成した文書は、その**人間が直接読む入口**を先に示す。公開ガイドは表示を実測したWeb URL、非公開報告は生成済み一時PDFのリンクを1件。検収できない場合は生成・保存・公開・実表示を分けて報告し、安全な通常テキストを代替にする。新Task/台帳や無用な毎回の承認は追加しない。
